# Decisions

One line each: decision — reason.

## Phase 0 (lead)
- Expo SDK 57 (React Native 0.86, React 19.2, Reanimated 4.5) with versions chosen by `npx expo install` — npm "latest" of RN libs is ahead of what SDK 57 supports.
- TypeScript 6.0.x everywhere — TS 7 (native port) is not yet supported by typescript-eslint (<6.1).
- pnpm 12 with `nodeLinker: hoisted` — Metro/React Native resolve most reliably from a flat node_modules.
- Contract packages are consumed as TypeScript source with explicit `.ts` import extensions — one source of truth for Metro, Next, Vite, Deno and tsx without a build step.
- Guests are Supabase anonymous users — one stable identity for events/sessions/storage; linking upgrades in place; RLS gates social writes with `is_member()`.
- The mobile app stays Expo Go-compatible (no custom native modules; `expo-sqlite/kv-store` instead of MMKV) — lets us drive iOS/Android simulators without native builds or CocoaPods.
- Bridge: the reply to `hello` carries the LaunchContext (what the prompt calls `init`) — one generic `reply` envelope for all requests keeps the SDK tiny.
- `gameplay.start` carries an SDK-observed `trigger` (tap/swipe/key) — lets the shell, simulator and reviewer detect "run started by a swipe" without seeing inside cross-origin frames.
- Added a `FAILED` card phase to the Swipe Contract — loading failures need their own retry state; ownership is the same as LOADING.
- Pause/resume messages are derived by reconciling `shouldRun(state)` after every transition — makes double pause/resume impossible (fuzz-tested).
- Local game host is path-based (`:5555/<slug>/<versionId>/`); production is one origin per game on `thumbcade.gg` — `*.localhost` subdomains don't resolve in simulators/emulators.
- `game-bundles` bucket is public-read locally (unguessable version UUID paths) — production serves from R2 behind the CDN.
- Protect triggers (roles, counters, status, live version) allow nested trigger updates and `enter_trusted()` security-definer RPCs — counters and approve/rollback must update protected columns.
- Review decisions are SQL RPCs (`approve_version`, `reject_version`, `rollback_to_version`, `takedown_game`) — one implementation for the portal, the CLI and the e2e script.
- Docker via Colima (Homebrew) — Docker Desktop needs interactive setup; Colima runs headless.
- Brand assets are generated from code (`scripts/build-brand.ts`) with opentype.js 1.3.4 — 2.0.0 produced NaN glyph coordinates for Mona Sans Display Expanded.
- Logo: a raised arcade button whose engraved ridges form a thumbprint whorl; five bold ridges (not six thin ones) so it survives 29–60 px.
- Logo rework (2026-10-14): the cap is `heat` red (a classic arcade button) instead of volt, which read as neon. The lower ridges resolve into pixels, smooth then half pixels then full pixels, so a real thumb turns into a game. The rings are circles on a 28-unit pixel grid so the pixel rows stay clean. The splash ripple uses `heat` to match the button.
- Logo variants (2026-10-15): `build-brand.ts` takes a variant, and the choice is kept in `brand/variant.txt`. `classic` has five fine ridges on a 28-unit grid. `bold` has three ridges on a 46-unit grid, so the print stays readable at icon and favicon sizes. `bash scripts/brand.sh <variant>` switches the variant and refreshes the mobile, portal and simulator copies.
- Accent is red (2026-10-14): app, portal, simulator and auth emails use `heat` as the accent to match the logo, and volt is gone from the palette. Text on red is ink, at 5.8:1; paper on red would be 2.9:1. Success states (toasts, "live" status, passed review checks, CLI connected) moved to a `success` green (#4CC38A dark, #3F7A00 light), because red now means both "primary" and "error". Where volt and heat used to mean feed and game in the Swipe Contract diagrams, the feed side is now paper. Not changed: the default `games.accent_color` in the init migration, the SDK standalone status dot, the reviewer overlay, `games/_kit` and the avatar palette.

## Integration (lead, Phase 2)
- Challenge share codes only carry a score the caller reached (`share-create` checks `best_scores`, respecting `score.order`) — otherwise anyone could post "beat my 999,999" under their name.
- Events ingest is capped at 600 per user per minute (`events` → 429; the app's bounded queue retries) — trending and ranking signals roll up from client events, so one install must not be able to steer them.
- Session tokens fail verification when `SESSION_SIGNING_SECRET` is under 16 characters, mirroring signing — a missing secret would otherwise accept empty-key HMACs.
- The WebView message origin check is exact (the origin itself, or anything under `origin + "/"`), not a bare prefix — a prefix also matches `https://slug.thumbcade.gg.evil.example`. iOS reports the page URL, Android's WebMessageListener the bare origin; both are unit-tested.
- A card's WebView is keyed by its controller instance as well as its reload counter — a replaced controller (pool reload, Fast Refresh) never saw the old page's hello/ready, so it needs its own page load.
- `create-thumbcade-game --local` writes `link:` dependencies under pnpm and `file:` elsewhere — pnpm copies `file:` directories with only their published files, and the in-repo SDK exports point at `src/`.
- `pnpm dev` stops its children with SIGINT and a 5 s SIGKILL fallback — the Supabase CLI ignores SIGTERM and was left running.
- The seed derives creator-dashboard social numbers from the real seeded rows (60 % of all-time over the last 14 days) and seeds yesterday too — independent synthetic rates showed more likes in 14 days than all time, and an empty yesterday read as a dead game.
- A paused run is dimmed (55 % ink) under the returning chrome — the spec brings the overlay and tab bar back in PAUSED, and without a dim the game's own HUD competes with them.
- The feed caption keeps its natural height (bottom-anchored, tighter rows under Dynamic Type) instead of a max height — at accessibility sizes the cap clipped the meta line; a few points over the preview inset beats losing content.
- Local auth runs with `enable_confirmations = true`, like production — `supabase config push` would otherwise ship the insecure setting, and the guest-upgrade code path gets exercised every day.
- `scripts/shoot.mjs` waits for `load` plus an optional quiet moment, not `networkidle` alone — pages with live game iframes may never go fully idle.
- The Android emulator runs with `-gpu host` (Metal), not SwiftShader — software WebGL kept qemu at ~550 % CPU, and Maestro taps took minutes; with the GPU all eight flows pass in 1–3 min each.
- Maestro's cold-start flow accepts PLAYING, ENDED or PAUSED after the tap — all three are only reachable through PLAYING, and a slow poll can land after a short run ends or after the 20 s idle pause.

## Creator & Games (B)
- SDK types are hand-written mirrors of the protocol (type-level equality tests) — the published package needs no dependency, not even type-only; zod-inferred types would drag zod into the d.ts.
- `@thumbcade/sdk/host` validates with the protocol's zod schemas and is published with zod as an optional peer — hosts need validation; games never load it.
- SDK connects its transport at import (not at `init()`) — an offscreen preload can receive `pause` before the game calls init.
- Start trigger = movement of the active/last pointer sequence (≥ 12 px = swipe), key within 1 s = key, else none — the SDK only sees what happens inside the game document.
- After `input.cancel` the SDK swallows the rest of the gesture at window capture (moves, ups, compat mouse events, click) — "no half-jump" has to hold even for games that ignore pointercancel.
- `tc.loop` passes dt in seconds, 0 on the first frame and after a resume, clamped to 0.1 s — paused time must never become physics time.
- Standalone mock host: storage in localStorage, a local best-score "leaderboard", a shadow-DOM dev HUD whose taps are intercepted at window capture so the game never sees them.
- Reviewer harness serves the game from 127.0.0.1 and the harness from localhost (different origins) with the production CSP, gzip, and the real swipe-contract machine — what it measures is what the app would do.
- Reviewer runs Chromium with site isolation disabled — CPU/network throttling must apply to the game iframe, which otherwise lives in its own renderer process.
- "Fast 4G" = Chrome DevTools preset (9 Mbps down, 1.5 Mbps up, 165 ms adjusted latency) + 4× CPU throttle for the ready() budget.
- Launch games share `games/_kit` (session lifecycle, procedural WebAudio SFX, particles, easing, recognizers, shake/hit-stop, fonts); two OFL fonts are bundled per game: Departure Mono (22 KB) and a printable-ASCII subset of Mona Sans Display Expanded Black (25 KB).
- Kit audio suspends the AudioContext whenever the game is muted or paused — pause always means silence, and a muted preview costs no CPU.
- Game icons are SVG artwork in `games/<slug>/art/icon.svg`, rendered to 1024² PNG by the kit's Vite plugin with sharp at build time.
- `tc.feedback` is delivered only during a run (+1.5 s after `gameplay.end`) and never while paused — attract-mode demos must not buzz someone scrolling past; enforced in the SDK so every game gets it.
- Games create their AudioContext while booting when they launch unmuted — creating it inside the first tap measured 120-160 ms (a long task after ready).
- Reviewer WebGL runs on the real GPU (ANGLE/Metal) on macOS — SwiftShader can't hold 60 fps for the 3D games; Linux reviewers need a GPU host (documented in GAPS).
- Reviewer measures long tasks under the 4× CPU throttle (load + the first 2.5 s of attract mode), then unthrottles for fps (GPU) and the interaction script — fps under CPU throttling measures the reviewer's machine, not the game.
- Reviewer: runtime requests to other origins are reported under `static_scan` — ReviewCheckId has no separate network check.
- Reviewer `gameplay_end`: 25 s without input, then up to 70 s of scripted taps/swipes; "warn" (not "fail") when no game over is observed — a human reviewer checks long-session games.
- Reviewer swipe test mimics the feed: a 220 pt vertical swipe in attract mode with FEED_GESTURE_BEGIN dispatched at the first move step; any gameplay.start during it fails `no_swipe_start`.
- Simulator and game share one origin (`thumbcade dev` serves the prebuilt simulator at `/` and the game at `/__game/` through Vite middleware mode with HMR; the monorepo simulator serves launch games at `/__games/`) — the simulator observes input through the probe, whose listeners register before the SDK's, so it can arbitrate drags the SDK swallows after `input.cancel`. Cross-origin URLs load with Dock/keyboard/wheel navigation only.
- Simulator models the 3-slot pool: the dev game's WebView is recycled two cards away and preloaded OFFSCREEN (pause after ready) when it is a neighbor again.
- Simulator chrome is a visual twin of the app; the controls that matter to a game work (like/save/follow toggles, comments/share sheets that SUSPEND the card, Dock mute, result card, resume pill). Everything else on the chrome is inert, not a fake action.
- creator-publish answers pre-upload failures with HTTP 4xx `{error, message, issues}` (contract request B2); the first publish claims the slug and copies the bundle icon (and poster) into game-assets as the game's profile picture.
- CLI auth: `Authorization: Bearer tc_…` first; if the functions gateway rejects a non-JWT bearer, retry with the anon key + `x-thumbcade-token` (until `verify_jwt=false` for creator-publish is live, contract request B1).
- CLI credentials live in the OS keychain (macOS `security`, Linux libsecret `secret-tool`), else `~/.config/thumbcade/credentials.json` (0600), keyed by backend host; `THUMBCADE_TOKEN` wins for CI.
- `thumbcade dev --device` prints a QR for `thumbcade://dev?url=<encoded http://<lan-ip>:<port>/__game/index.html>` — the app's developer menu opens that URL in a DEV card.
- create-thumbcade-game uses opentype.js 1.3.4 (2.0.0 breaks Mona Sans Display Expanded glyph coordinates, same as the brand build) to turn the bundled OFL fonts into SVG paths, rendered with sharp — real icons and posters with no system fonts or browser.
- Template projects use system font stacks and a `release` npm script (not `publish`, which collides with npm's lifecycle).
- `pnpm games:build` captures posters from attract mode through the reviewer harness (preview insets applied, 405×720 at 8/3 DPR = 1080×1920 JPEG) and ships each poster inside its bundle with `manifest.poster` set.
- Every game in the house style belongs to Thumbcade Studio; the other seed creators each have a look of their own (see "Library expansion: house and creator games (2026-10-17)").
- Pixi games import `pixi.js/unsafe-eval` (it makes Pixi v8 run without eval under the CSP) and stop `Ticker.shared`/`Ticker.system`, driving them from `tc.loop`; Three.js games render inside `tc.loop`, never `setAnimationLoop`.

## Player Platform (A)
- Gesture spike (§5.6) PASSED on iOS 27 (iPhone 18 Pro sim, Expo Go 57) and Android 16 (AVD `thumbcade_pixel`, Expo Go 57.0.9) with the primary approach: RNGH `Gesture.Pan().manualActivation(true)` on the pager (activation decided in `onTouchesMove` from the §5.4 rules held in shared values) composed via `simultaneousWithExternalGesture` with a `Gesture.Native()` wrapping each WebView. Verified by Maestro (`apps/mobile/maestro/spike/`): (a) taps reach the WebView with 0 ms (iOS) / 1 ms (Android) between RNGH `onTouchesDown` and the page's `touchstart` (`Date.now()` on both sides); (b) a vertical swipe in PREVIEW is claimed by the feed and the game is sent `input.cancel`; (c) in PLAYING with `vertical: true` a surface swipe reaches the game (swipe counted, no feed claim) while a pan starting on the Dock moves the feed; plus a `vertical: false` game in PLAYING still yields a deliberate swipe to the feed. The `input.inject` overlay fallback is therefore not needed and not shipped.
- Pan failure rule added on top of the contract's activation rule: the surface pan fails (the game keeps the gesture) once |dx| ≥ 16 pt and |dx| > |dy| — the contract defines when the feed claims, not when it gives up; without this a slow horizontal drag could be claimed late.
- Expo Go on Android shows its developer-menu onboarding once per install; Maestro flows dismiss it conditionally. Android Maestro swipes on the Dock target the element (`swipe from: id`) because a percentage near the bottom lands in the system gesture area.
- Metro runs without `--localhost` (it binds IPv6-only `::1`, which Expo Go on the iOS simulator cannot reach at 127.0.0.1); `REACT_NATIVE_PACKAGER_HOSTNAME=127.0.0.1` keeps the manifest URL local. Android uses `adb reverse tcp:8081 tcp:8081`.
- The Android emulator must not use the default console port 5554: its ADB port 5555 collides with the game-host. Start it with `emulator -avd thumbcade_pixel -port 5562 …` (ADB then uses 5563).
- Edge functions are served by `supabase functions serve --env-file supabase/functions/.env` (the CLI's `supabase start` runtime mounts no functions in this setup and stops serving when the stack restarts). Relative imports of `packages/protocol/src` work inside the edge runtime, so functions validate with the real contract schemas (per-function `deno.json` maps `zod` → `npm:zod@4.6.7`).
- Game host proxies the public `game-bundles` bucket with an in-memory LRU (bundles are immutable), sends the exact §6 CSP plus `frame-ancestors` for the portal and simulator, CORS only for an allowlist (never `*`), ETag/304 and range requests.
- Feed ranking (`rank_feed`) is SQL with weights from `feed_config`; the edge function owns the cursor (`seen` ring, position, last creator/tag) so diversity holds across pages. With a small library the feed recycles least-recently-served games (never the last 6 cards) so it is infinite.
- Exploration slots use Thompson sampling with Beta draws from uniform order statistics in plpgsql; games with < `exploration.maxImpressions` impressions qualify.
- Score integrity: `session-start` issues an HMAC-SHA256 token binding session, user, game and issue time; `session-end` rejects bad tokens, scores over `manifest.score.max`, NaN/negative scores, impossible durations (claimed > server elapsed + 5 s, or elapsed < 400 ms) and double ends. Guests get `accepted:false, reason:"guest"` but still receive their best and today's percentile.
- Push fan-out: pg_cron → pg_net → `notify` every minute; the function base URL and service key live in Vault (`set_runtime_secret`), set by the seed locally and by ops in production.
- Comment filter normalises leetspeak and matches whole words from `public.moderation_words`; 5 comments / 60 s / user; one pinned comment per game.
- Seed deletes seed users one at a time after clearing their social rows in bulk (parallel deletes deadlock on counter triggers). Seed icon/poster URLs carry `?v=<versionId8>` for cache busting.
- Each card is a `CardController` (plain TS) that owns the contract state, executes every `transition()` effect, terminates the bridge (zod + per-type rate limits) and the session lifecycle; React only subscribes (`useSyncExternalStore`). It is unit-tested without React Native.
- The pager keeps a pool of three slots; slot k hosts the card whose index ≡ k (mod 3), so a forward swipe recycles the slot furthest behind. Slot positions are `feedIndex·H − scrollY` on the UI thread; the commit decision runs in the release worklet (`resolveRelease`) and only the activation bookkeeping hops to JS.
- Rules for the surface, two-finger and Dock pans are pushed into one shared value from `gestureConfigFor(phase, controls)` whenever the active card's phase changes; the worklets call the contract's `claims()`/`resolveRelease()` directly (the contract functions are worklet-annotated and transform fine from the workspace package).
- WebView budget: only the focused pager mounts game WebViews; a pushed scoped feed claims the budget and the home feed falls back to posters until it is focused again. The `ready()` timeout pauses while the hosting screen is hidden (hidden WKWebViews stop rAF).
- Shared WebView data store (not incognito) with `sharedCookiesEnabled={false}`/`thirdPartyCookiesEnabled={false}`: keeps the HTTP cache warm between plays; production isolates games by origin (`<slug>.thumbcade.gg`). Navigation is locked to the version's base path, not just the origin.
- Global sound defaults to off; games start muted in previews until the user turns sound on (Dock or Settings); the setting is persisted.
- Idle auto-pause (20 s) means unattended runs never end on their own; the resume pill brings them back.
- Age screen stores only the band, computed from the lower bound of the possible age (birthday may not have passed) so the boundary errs on the protective side. Under-13 players can play age-appropriate games but social features stay locked.
- Comments, likes, saves, follows, reports, blocks go straight to PostgREST under RLS with optimistic cache patches across every query that shows the same game or person; edge functions are only used where a trusted server step is required (ranking, sessions, shares, deletion, push).
- Share codes are members-only (protocol); guests share the plain game URL. The seed's challenges come from named demo members and carry that member's real best.
- `paperMute`/`textMute` (3.4–4.0:1 on ink) is used only for placeholders, disabled states and decorative glyphs; all readable text uses `textDim` or brighter (≥ 7.2:1).
- Dynamic Type: text scales up to ~1.35× (display sizes less); the feed caption is capped at 1.12× because it must fit the fixed `captionHeight` inset that games are told about.
- Cartridge → game page "shared element" is implemented by measuring the cartridge and animating a floating icon into the hero slot (Reanimated 4's shared element transitions need a native feature flag that Expo Go doesn't have).
- Brand marks are rendered from the design-tokens SVG files (embedded verbatim by `scripts/gen-brand.mjs` for `SvgXml`), never redrawn.
- iOS-only WebView props (`dataDetectorTypes`, `textInteractionEnabled`, `keyboardDisplayRequiresUserAction`) are passed only on iOS: on Android/Fabric, `dataDetectorTypes` crashes the RNCWebView props parser.
- `expo-notifications` and `expo-media-library` are loaded lazily: Expo Go for Android logs an error on importing the former and lacks the latter's native module.
- App Store guideline 4.7 (read 2026-10-14 at developer.apple.com/app-store/review/guidelines): HTML5/JS mini games may be offered outside the binary if the app takes responsibility for them and meets 4.7.1–4.7.5. How the player complies: **4.7.1** privacy rules apply to games too (games never see tokens, email, device ids or the real user id; per-game opaque player id), objectionable-content filtering (human review before live, age ratings, comment word filter), report (games, comments, users) and block are in the app, with a moderation queue in the portal; no digital goods in v1 (3.1 untouched). **4.7.2** games get no native APIs: the bridge exposes only lifecycle, score, storage, leaderboards, a share flow and *semantic* feedback that the shell maps to haptics itself. **4.7.3** no data or permission is shared with a game without consent: games get display name/avatar only, no permissions (camera, location, photos) are ever forwarded. **4.7.4** the index of software is the games table/feed with full metadata, and every game has a universal link (`https://thumbcade.com/g/<slug>`, wired as associated domain). **4.7.5** declared-age gate on first launch stores an age band; the feed filters by each game's age rating, and the game page shows the rating.

## Creator analytics and milestones (lead, 2026-10-14)
- A run counts as a play once the game ends it or once it reaches 3 s of active play (`QUALIFIED_PLAY_MS`, mirrored in `feed_config.analytics`; a test keeps them equal) — counting instantly would count a tap followed by a swipe; a long threshold would drop real short runs (a Flapjack death at 2 s). 3 s is twice the 1.5 s fast-skip window. Runs that never qualify show up as bounced starts.
- The public play count moved from session start to qualification, and counts at most 100 plays per person per game per UTC day — the feed's "▶ plays" and the creator's dashboard are now the same number, and one install can't inflate it.
- Playtime is active time in PLAYING while the game runs, measured by the shell (`CardController` run clock) and reported through `session-progress` (once at qualification, then on interruptions, at most every 5 s) and `session-end` — the server clamps it to wall-clock time + 2 s and never lowers it. Wall-clock `durationMs` stays for the impossible-duration check.
- Sessions by the game's creator or by admins are marked `excluded` when they start and never count anywhere — creators testing their own game would otherwise inflate it.
- Per-player aggregates (`game_players`, `game_player_days`) have no client policies; creators see only owner-checked `creator_*` RPC aggregates — the tables hold user ids.
- A player's playtime is recomputed from their sessions in the trigger; only the game's total adds deltas — incremental per-player deltas double-counted when several sessions arrive in one statement (the seed).
- Range player counts are stored windows (`players_7d`, `players_28d`) computed by the rollup, not sums of daily players — summing days counts returning players twice.
- Sources and versions are compared from the daily rollup (`plays_*` by launch reason, the version live when the day was rolled up), not from session scans — cheap at any size and consistent with the headline numbers; release days go to the version that was live at that day's last rollup.
- The funnel is per card view (viewed → started → played → played again); "came back another day" is shown as day-1/day-7 return of new players, not as a fifth funnel step — it counts people, not card views.
- Milestones are awarded right after each rollup (same cron job), once per game, kind and threshold. At most one milestone notification per game per UTC day (the most exciting one wins: taking off, then players, playtime, best day, firsts). Best day and taking off have a 7-day cooldown. The migration awarded existing milestones silently so deploys don't flood inboxes.
- Drops never notify and render in neutral text; only rises use the success color — a creator dashboard informs, it doesn't alarm.
- A milestone is public only after its creator shares it (`share_milestone` → `/m/<code>`); the card links straight into the game, like challenge pages.
- OG cards inline remote images (`imageDataUrl`) — next/og refuses loopback URLs (SSRF protection), so every card with a game icon failed locally; the font path also falls back to the workspace layout because Turbopack dev resolves packages to virtual paths.
- The seed's all-time totals scale the visible 28 days by the game's age (with a launch bump) instead of the old 6–36× multiplier — the dashboard puts all-time and 28-day numbers side by side, so they must agree. Locally the seed dates `playtimeSince` to the first seeded launch.
- The mobile Creator Hub's dashboard links now open `/creator` — `/dashboard` never existed in the portal.

## EU / German compliance (lead, 2026-10-14)
- Legal text lives once, as data, in `packages/legal` (`@thumbcade/legal`): operator details (`OPERATOR`), retention periods (`RETENTION`) and the Imprint, Privacy Policy, Terms and Community guidelines. The app renders it natively (`/settings/legal?doc=…`), the portal at `/legal/<doc>` — the two used to say different things. English only, like the rest of the product.
- The operator's address appears only where the law needs it: the Imprint and the controller block of the Privacy Policy. No "established in" statements elsewhere, no named supervisory authority (Art. 13 only requires stating the right to complain), no consumer-arbitration notice (§ 36 VSBG applies from 11 employees), no ODR link (platform shut down in 2025).
- No cookie banner: the portal sets only the Supabase session cookie and the web player uses local storage for saves the player asked for — both strictly necessary. Adding any analytics or third-party embed changes this.
- Data export is server-side (`account-export`, service role, filtered by the caller) so it includes what RLS hides from players: usage events, hashtag weights, per-player analytics aggregates, sign-in identities. The app shares the JSON; the portal downloads it from `/account/export`. Guests can export and delete too.
- Retention is enforced, not just written down: daily cron `thumbcade-retention` drops `feed_events` partitions older than 90 days (rollups stay) and deletes guest accounts with no sign-in, session refresh or token rotation for 12 months. A test (`scripts/test/privacy.test.ts`) keeps the cron arguments equal to `RETENTION`.
- Web account deletion redirects to `/account/deleted`; a success state inside `/account` can't render because the cleared session cookie re-renders the protected page.
- DSA: the Imprint names one point of contact (Art. 11/12); the Terms describe moderation tools, reporting illegal content without an account, and how to contest a decision (Art. 14/16). As a micro/small enterprise Thumbcade is exempt from the online-platform duties in Art. 19 onwards (complaint system, transparency reports, recommender transparency) — the Privacy Policy still lists the feed's main ranking signals.


## Launch games: licenses and de-cloning (2026-10-16)
- Every game bundle ships its license texts under `licenses/`: `libraries.txt` is Vite's `build.license` report (name, version, license, full text of each bundled npm package) and the kit adds the OFL text of each kit font in the bundle — MIT, ISC, BSD and the OFL all require the notice in every copy, and minified chunks keep none. `.txt`, because the game host, the reviewer and creator-publish already serve it as `text/plain`.
- The game title font is "TC Display Black", a renamed subset of Mona Sans Display Expanded Black — a subset is a Modified Version under the OFL and Mona Sans reserves the name "Mona". `games/_kit/scripts/fonts.ts` rewrites the name table after subsetting (original copyright, vendor and designer kept, license records 13/14 set) and fails if any record but the copyright still says "Mona". Departure Mono has no reserved name and ships unmodified.
- Game mechanics stay free to use, but a launch game must not copy a famous original's look and presentation (German UWG §4 Nr. 3, slavish imitation). Heatfall (then Helix Fall) became a forge: toothed iron grates with cooling slots on hex hubs, coolant vents with a cyan chevron pattern instead of red segments, a faceted ember with a halo instead of a ball, sparks instead of a paint splat on bounce, and its own charge rule (gaps stoke the ember, bounces cool it a notch, five charges melt the next grate and vent the heat front) instead of "three gaps in a row smash". New icon: one gear seen from above with the ember in its gap.
- Neon Chop (then Slice) dropped Fruit Ninja's presentation: no watermelon-coloured produce (hexberry is blue), no blade across a melon in the icon, three market lights under a centred score instead of X strikes top-right with the score top-left, light streaks and sparks instead of juice splats, and the surge cell (arcs into the three nearest produce and cuts them, never static) instead of a freeze item with a frost overlay. Seed comments no longer talk about bombs and fruit.
- Smaller hallmarks went too: Stackd's square ripple outline on a perfect drop is now the new floor's windows blazing, and Voltbrick's (then Breakout Neo's) silver riveted armoured bricks are smoked glass with glare and light cracks.

## Launch game names: trademark clearance (2026-10-16)
- Seven launch games were renamed, display name and slug, after an EU/German trademark check (EUIPO, DPMA and WIPO records via TMview and EUIPO's register, prior use in the German App Store and Google Play, German title protection for games under §5(3)/§15 MarkenG). Slugs are permanent once published, so this had to happen before launch. `THUMBCADE_BUILD_PROMPT.md` keeps the original names as the brief.

## Creator bundle safety (2026-10-17)
- Players are protected by the sandbox, not by reading code: the platform only ever receives a creator's built bundle, and every game runs on its own origin under a CSP with no outside network, with device features switched off and only the fixed bridge to talk through. The checks below close the gaps that sandbox leaves and make the bundle reviewable.
- **File types.** A bundle may only hold web code, data and media (`BUNDLE_FILE_EXTENSIONS` in `packages/protocol/src/publish.ts`), no hidden files, and no native executable under any name (`executableKind`: PE with a real `PE\0\0` header, ELF, Mach-O, universal binaries). `creator-publish` refuses offending uploads before anything is stored; `thumbcade validate` and the reviewer's manifest check report the same; `thumbcade publish` leaves out `.DS_Store`, `Thumbs.db` and `desktop.ini`.
- **Obfuscation fails, minification passes.** `obfuscationSign` in `@thumbcade/cli/checks` looks for obfuscator and packer fingerprints: ten or more `_0x…` identifiers, `eval(function(p,a,c,k,e,…))`, 500+ characters of only `[]()!+`, `eval`/`Function` of `atob`/`unescape`/`decodeURIComponent`, or 500+ `\x` escapes making up 8 % of a file. Calibrated against all 26 game bundles, 235 large library files from `node_modules` (Next.js, Babel, Terser, Vitest, chess.js and more) and the npm builds of Phaser 4.2.1, Pixi 8.22.0 and Three 0.186.1: no hits.
- **WebRTC** isn't covered by any CSP directive, so it could carry data out. The static scan fails on `RTCPeerConnection` and friends (only developer tools such as Babel and Terser mention them; no game library does), and the probe hooks `createOffer`, `createAnswer`, `setLocalDescription` and `createDataChannel` on the prototype, so the reviewer's network check also catches a name built at runtime or a constructor taken from a blank iframe. Clients can't block it: a same-origin `about:blank` iframe hands out a fresh `RTCPeerConnection`, and a host can't inject into a cross-origin frame on the web. What a game could leak is limited to what it has: the anonymous player id, display name and avatar URL, and anything typed into it.
- **Navigation.** The app's WebView already refuses any navigation outside the version folder before a request is made. On the web a game can navigate its own iframe (no sandbox flag prevents it); tested in Chromium, a page with no CSP let a game's redirect reach an outside server with data in the URL. The portal now sends `Content-Security-Policy: frame-src <games origin>` on every page (`apps/portal/src/lib/frame-policy.ts`, wired in `next.config.ts`), and the browser refuses such a redirect before any request leaves. The web player drops a frame that loads within a second of a `frame-src` violation and says the game was stopped. The static scan warns on `location = …`; the reviewer's routing records a frame navigation as an off-origin request.
- **Flashes.** The reviewer captures the page with the CDP screencast at 60 fps (every composited frame) for 3 s of attract mode and up to 30 s of the run, and `services/reviewer/src/flashes.ts` applies WCAG 2.3.1. A general flash is opposing luminance changes of at least 0.1 with the darker side below 0.8; a red flash is opposing changes of at least 20 in (R − G − B) × 320 involving saturated red. Each 10 px cell is tracked as a zig-zag; a 320 px square (10° of view at about 30 cm) makes a transition when a quarter of its cells turn the same way on the same frame (two halves a frame apart count once), so a full-screen flash or a flipping checkerboard counts and moving objects don't: they darken the cells they enter and brighten the ones they leave at once. More than 3 flashes in any second fails. A first version only asked that cells flash in the same second, not at the same moment, and failed Wobble Up for its spring launch (cookies and platforms scrolling fast over a light sky); its recording now measures 0.
- Contract additions, made at the owner's request and additive only: the `flashes` review check id and the bundle file helpers in `packages/protocol/src/publish.ts`.

## Frame rate fixes: riso screens, Lanternline stepping (2026-10-25)
- Longhop and Leapwater ran at 0.8–2.6 fps in iOS WebKit while playing. Cause: every halftone tint was a pattern rotated to its ink's screen angle at fill time, and WebKit (CoreGraphics) fills a rotated or scaled pattern on a very slow path. In the simulator 40 fills drop from 60 to 0.7 fps when the pattern is rotated; the plates, grain and multiply blending were not the problem. `riso.ts` now draws the turned dot grid into the tile itself, and the pattern is only pinned to the paper. A turned grid tiles a square only at angles atan(p/q), so screen angles snap to the nearest one (15° → 14.0°, 75° → 76.0°, 45° stays), within about 1° and with dot spacing under 1 % off. After: 55–60 fps. Leapwater's veil pattern is drawn in device pixels for the same reason. Halftones drawn inside a rotated transform (falling leaves, the kangaroo's death tumble) still take the slow path, but they cover little area.
- Lanternline's sim now advances each frame in equal substeps that add up to the frame's time, instead of fixed 1/120 s steps with a carried remainder. In slow motion and on 120 Hz screens the old stepping alternated frames that moved with frames that didn't. At a steady 60 or 120 Hz the physics is unchanged. Slow-motion entries and the first-run wait ease in over a few frames, and the drawn figure rounds the corner of a catch on a stiff spring (≤ 7 wu, ~0.1 s); collisions still use the body.

That is 181,720 words of 3-16 letters, 468 KB gzipped. The common list (seeding, the pen's demo, "missed") is SCOWL english and american up to size 35: 38,788 words, of which the 10,795 up to size 20 count as everyday words and are revealed first. `scripts/words.ts` builds both from pinned, checksummed downloads; licences ship as `licenses/words.txt`. The common list (104 KB gz) loads before `ready()`; the broad one loads after the first frame and is searched in place by a binary search over the text, so it costs no parsing. Checked on throttled Fast 4G with the list held back 4 s ("stoa" at 2.6 s, accepted on arrival).

Mild hard words made of the commonest letters (ass, arse, rape, damn, crap…) are only kept off straight lines a player could read: checking every bent path for them threw away a third of all boards for words nobody can see. Soft words (an innocent first meaning and an adult second one, or adult topics) are accepted if traced, but never planted, demoed or revealed. The bundle ships hashes of the hard words for the board check, never the words.

The clock is 70 s and a round never runs past 90 s: time back fills the page up to its ninety seconds. A numbered seal every fourth word; using all sixteen letters at least once pays 10 points and 3 s, once.
- Feel: a tile is picked up within 42 % of its width around its centre, so the corners stay dead and a diagonal never snags its neighbours; the finger's path is sampled between pointer events, so a fast stroke can't skip a tile; going back onto the previous tile lifts the stroke off. The traced word shows live above the board with its length and value, and gets a vermilion rule as soon as it is a word we know (an assist, not a spoiler: the board's words aren't listed). Every new letter plucks a marimba note one step higher. A word stamps: the ink soaks back into the tiles, the points fly to the score, long words ring a bell, splash ink and shake the page a little. An unknown word shakes softly and leaves a smudge; a repeat says "already found" and underlines the earlier one; nothing ever costs time or points. ## Curlwall (2026-11-06)
- A house game (Thumbcade Studio, Three.js): free kicks under floodlights. A tap starts the run; an upward flick that starts anywhere in the lower 62 % of the screen kicks. Mild assist: up to 0.9 m outside the post or over the bar is squeezed back just inside, and a flick near a corner ring is drawn toward its centre; anything wilder stays wild. - **The pressure: a rising starter, not a clock.** A sourdough starter at the bottom of the tin rises all the time (0.07 + 0.0085·t units/s), lifting the whole pile toward the rim, and every merge knocks it back, as bakers knock back risen dough: 0.1 units for a gumdrop up to 1.2 for the party cake, 30 % harder per chain link (`src/run.ts`). - **Ladder and jackpot.** Ten tiers were too deep for feed-length runs (nobody baked the top, a quarter of experts reached the second-to-top), so there are nine. - **Physics** (`src/physics.ts`, pure, deterministic, no allocation while stepping): position-based dynamics, 1/120 s steps of four 1/480 s substeps, circles up to 120, O(n²) pairs, mass by area, no restitution (clay doesn't bounce), positional Coulomb friction (μs 0.45, μk 0.3). Three fixes made it stable: overlap that this substep's motion didn't create (a merge swelling into its neighbours, a piece squeezed between two) is eased out without adding speed, and the dough and walls discount those eased pushes too, so a merge lifts the pile a few pixels and never throws it (settled pieces stayed under 6 units/s upward in real runs, against 21 before); hairline leftovers inside a resting stack are resolved in full, or easing them along their slopes made the pile creep; and contacts between pieces still for 0.35 s hold fully, with sideways sleep after 0.5 s, so piles settle to exact stillness instead of drifting. Merges happen on touch (0.03 units of slack), at the contact point, and the new piece swells from its parent's size over 0.14 s; a fresh piece can chain after 70 ms. Drawing interpolates between steps, so motion is even at 60 and 120 Hz.

## Clatterlane: glow bowling against the clock (2026-11-06)
- A house game (Thumbcade Studio, Three.js, house fonts and UI), electric azure accent `#08A0F0` (CIEDE2000 ΔE 10.8 from every accent in the tree, nearest Voltbrick's `#4D8DFF`; 6.7:1 on ink). The palette is crowded; the most distinct saturated hues left were cyan (Weavefire's neighbourhood, so out) and this azure.
- **Name.** Screened like the other new names: web searches, the App Store (US and DE, through Apple's search API), Google Play (US) and Steam (DE); TMview refused scripted requests, so no register search (`docs/GAPS.md`). Dropped: "Pinfall" (an App Store bowling score keeper of that name), "Glowlane" (an existing App Store game), "Pinsweep" (an App Store app "PinSweep"), "Hookbolt" (a hardware item, next to the party game "Hookbots"). "Clatterlane" and "Clatter Lane" turned up no game, app, alley or brand; the nearest names share only the word "clatter" ("Clatter" on Steam, a robot tactics game; "Clatter Smash", a physics puzzle; "Clatter Throne" on itch.io). Slug `clatterlane`. Copy names no alley, ball maker, league or other game.
- **Format: racks against the clock, not ten frames.** A run starts with 22 s; the clock burns 1 s/s at first and faster the longer you last (1 + (t/66)^1.5, at most 2.6), runs while you aim, while the ball rolls and while the pins come down, and waits for the 0.5 s sweep. A strike resets the rack at once and gives 5.2 s back (less in later racks, more on a glow rack, +0.45 s per chain level, +1.5 s for the turkey); otherwise the second ball goes at the leave, a spare gives 3.3 s and a converted split 3 s more, and the rack resets after the second ball either way. Each pin gives 0.1 s. The clock is capped at 32 s. An idle player hears the buzzer after 20 s (the reviewer measured 19.8 s); nobody's clock drops below 14 s in the first 10 s.
- **Rewards.** Pins 10 each; a strike is 300 × the chain; back-to-back strikes build a named chain that multiplies everything: DOUBLE ×2, TURKEY ×3 (+500 and bonus time), HAMBONE ×4, FIVE-BAGGER ×5. A spare (+150) or an open frame ends it. Strike and spare are celebrated differently: a strike slows time to 0.35× just before the ball meets the head pin, hits a short hit-stop, flashes, shakes and bursts in the chain's colour with a rising arpeggio, and the lane lights change colour by chain level (azure, pale azure, pink at the turkey, gold at the hambone, warm white at five); a spare gets a chime and a paper-coloured burst. A split is named on the first ball ("7-10 SPLIT · CONVERT IT FOR +500"); converting one pays 500 (1,500 for the 7-10, "THE BIG ONE") with slow motion, confetti and a fanfare. Every fifth rack is a glow rack: the pins glow pink, points double and a strike buys 25 % more time. The last 6 s are the clutch: pins count double, the clock pulses (≤ 2 Hz) and ticks, and a ball still rolling at the buzzer counts ("TIME · LAST BALL STILL COUNTS") but buys no time. A new best mid-run gets a banner and confetti.
- **Gutters are softened.** The bumpers are up for the first two racks (glowing rails over the gutters; the ball bounces back in, a little slower), with "BUMPERS DOWN · MIND THE GUTTERS" when they go. After that, the first gutter ball off a full rack each run is a free re-roll ("ONE GUTTER ON THE HOUSE"); later ones read "GUTTER · SHAKE IT OFF" in dim paper with a soft dunk, no shake, no penalty beyond the lost ball. An open frame with one pin left reads "SO CLOSE · ONE PIN STOOD ITS GROUND"; a pin that rocked and stayed up gets "IT WOBBLED... AND STAYED".
- **Input.** A tap starts the run; during play an upward flick that starts in the lower 62 % of the screen bowls. The flick's direction, followed from the ball onto the lane through the aiming camera, sets the heading (calmed to 72 %: the lane is a hundred pixels wide at the pins); its speed (420-2,600 px/s) sets the pace (7.6-13.2 m/s); its sideways bow sets the hook, Curlwall-style: the ball follows the way the swipe's end turns (a path bulging right hooks left), with a dead zone for a thumb's natural arc. The hook is a lateral pull that ramps in from 5.2 m to 9.6 m down the 12 m lane, so it bends late like a real ball leaving the oil; slower balls hook more. A too-slow flick doesn't bowl ("FLICK A LITTLE FASTER") and costs nothing; sideways and downward swipes are ignored; a cancelled gesture does nothing; a flick made while the rack is still being set waits for it. `controls.vertical: true`, input `swipe`.
- **Invisible assist.** The ball's line is integrated (the same steps as the solver) to where it crosses the head pin's row, or the key pin's row on a spare; that error against the target is shrunk inside a window and fades out over one more (monotonic, so a flick further right never lands further left). The target is the nearer pocket for the hook's direction on a full rack (6 cm beside the head pin on its own side, 8 cm on the far, "Brooklyn" side) and the line through the most standing pins on a leave. Rack 1: 62 % pull within ±22 cm; it eases to 30 % within ±13 cm by rack 10, and spares get 60 % of it.
- **Pins: our own solver** (`src/pins.ts`, pure, 1/480 s fixed step, no allocation while stepping, about 1-3 ms a throw). Each throw is simulated to rest the moment it leaves the hand, recorded at 120 Hz and played back, so outcomes are reproducible and the game knows a strike is coming before it lands. Collisions live in the lane plane: the ball is a disc, each pin a capsule (its axis projected onto the deck). Standing pins tip about their base edge like an inverted pendulum (critical angle 10°): a light touch wobbles and settles, a firmer one tips past the edge and topples slowly, and a hit that gives a pin more than 2.3 m/s launches it, tumbling end over end, landing, sliding and spinning into others (messengers), off the kickbacks and into the pit. Ball-pin restitution 0.62, pin-pin 0.5, kickbacks 0.25; loose pins spin at most 12 rad/s. These were tuned with a sweep over entry point, hook and speed (`test/pins.test.ts` keeps it): a hooked ball into the pocket strikes 78-88 %, a straight one 51-76 %, the Brooklyn side about half, a light hit 4-7 %, head-on about 1 % (it leaves 4-7-10s and 7-10s, as in real bowling). The pinsetter sets each rack a few millimetres off, seeded per rack. Every impact plays a wooden tok pitched up by the throw's impact count so far, so the clatter climbs as the rack explodes.
- **Look, de-cloned.** A single lane floating in a dark alley: midnight-stained maple boards (39 of them), accent arrows and foul line, a matte lane over faintly mirrored pins with a sheen down the middle and a pool of light under the rack, a strip of lane lights along each gutter lip that chases the ball, dim neighbouring lanes with their own racks, a dark masking unit, a sweep bar that rakes the deck. Pins are turned from a real tenpin outline with an azure neck band; the ball is our own deep blue with an accent marble swirl. The ball leaves a thin light trail that shows its hook. No alley, ball, pin or league brands, no cosmic-bowling carpet, no scoreboard of frames, no recreation of any bowling game's presentation; the masking unit carries no text (anything bright there sat behind the HUD).
- **Camera.** The aiming view sits behind and above the ball and is solved per screen so the ball is at 80 % and the head pin at 33 % of the height (fov 28° on phones); while the ball rolls the camera chases it down to about 4 m from the pins, holds while they fall, and glides back during the sweep. Reduce Motion cuts between the two views instead and drops slow motion, hit-stop and most of the shake.
- **HUD.** Score in the middle with the chain chip under it, the clock on the left with its own row for seconds back ("+5.2S BACK") and the clutch or bumper note, the rack, a pin diagram of what's standing and the ball number on the right. Banners sit in their own band under the HUD on near-opaque plates; points rise from the pins into their own rows below the band, on plates (lead QA, 2026-11-06). The first-run hint (a ghost finger flicking a curved swipe, "FLICK UP THE LANE TO BOWL / CURVE YOUR SWIPE TO HOOK IT") has its own plate and stays until the first pins fall (`tc.storage` key `hint`).
- **First 3 seconds and game over.** Attract mode is the real game bowled by the pilot (a good bowler who never botches one) through a ghost finger, with the camera chasing each ball, under the title, "GLOW BOWLING AGAINST THE CLOCK", the best score and "TAP TO PLAY", clear of the preview insets. Game over draws strikes, spares, best chain and racks, a bar against your best and one hint picked from the run (gutters, head-on hits, missed spares, no strikes, short chains), in the band between the shell's result card and the caption; standalone adds the score and "TAP TO BOWL AGAIN".
- **Headless pilots** (`pnpm --filter @thumbcade-games/clatterlane pilot`, 200 runs per skill, the same flick, aim and assist path as a thumb; bowlers pick a pace and a hook, the pocket or the leave's key pin, and flick with human-sized errors in swipe angle 0.018-0.078 rad, speed 8-24 %, bow 0.022-0.06, a per-run pull to one side they unlearn, and 0-8 % botched flicks): run length p10/median/p90 novice 34/42/56 s, casual 36/50/65 s, good 47/62/75 s, expert 57/73/86 s; strikes 38/42/46/55 %, spares 51/56/70/74 %; turkeys in 17/26/45/69 % of runs.
- **QA hook, build time only.** `VITE_AUTOPLAY=novice|casual|good|expert` lets the pilot bowl real runs through the same input path; each run draws its racks and the pilot's flicks from its own seed (launch seed and run number), so an autoplayed run repeats whatever attract mode did before it. `shoot.json` (normal build) shoots attract, the first-run hint, a real flick's impact and an idle game over; `shoot.qa.json` on an expert autoplay build shoots a 7-10 split, a glow rack and the game-over summary. A normal build has none of it.
