# Decisions

One line each: decision — reason.

## Phase 0 (lead)
- Expo SDK 57 (React Native 0.86, React 19.2, Reanimated 4.5) with versions chosen by `npx expo install` — npm "latest" of RN libs is ahead of what SDK 57 supports.
- TypeScript 6.0.x everywhere — TS 7 (native port) is not yet supported by typescript-eslint (<6.1).
- pnpm 12 with `nodeLinker: hoisted` — Metro/React Native resolve most reliably from a flat node_modules.
- Contract packages are consumed as TypeScript source with explicit `.ts` import extensions — one source of truth for Metro, Next, Vite, Deno and tsx without a build step.
- Guests are Supabase anonymous users — one stable identity for events/sessions/storage; linking upgrades in place; RLS gates social writes with `is_member()`.
- The mobile app stays Expo Go-compatible (no custom native modules; `expo-sqlite/kv-store` instead of MMKV) — lets us drive iOS/Android simulators without native builds or CocoaPods.
- Bridge: the reply to `hello` carries the LaunchContext (what the prompt calls `init`) — one generic `reply` envelope for all requests keeps the SDK tiny.
- `gameplay.start` carries an SDK-observed `trigger` (tap/swipe/key) — lets the shell, simulator and reviewer detect "run started by a swipe" without seeing inside cross-origin frames.
- Added a `FAILED` card phase to the Swipe Contract — loading failures need their own retry state; ownership is the same as LOADING.
- Pause/resume messages are derived by reconciling `shouldRun(state)` after every transition — makes double pause/resume impossible (fuzz-tested).
- Local game host is path-based (`:5555/<slug>/<versionId>/`); production is one origin per game on `thumbcade.gg` — `*.localhost` subdomains don't resolve in simulators/emulators.
- `game-bundles` bucket is public-read locally (unguessable version UUID paths) — production serves from R2 behind the CDN.
- Protect triggers (roles, counters, status, live version) allow nested trigger updates and `enter_trusted()` security-definer RPCs — counters and approve/rollback must update protected columns.
- Review decisions are SQL RPCs (`approve_version`, `reject_version`, `rollback_to_version`, `takedown_game`) — one implementation for the portal, the CLI and the e2e script.
- Docker via Colima (Homebrew) — Docker Desktop needs interactive setup; Colima runs headless.
- Brand assets are generated from code (`scripts/build-brand.ts`) with opentype.js 1.3.4 — 2.0.0 produced NaN glyph coordinates for Mona Sans Display Expanded.
- Logo: a raised arcade button whose engraved ridges form a thumbprint whorl; five bold ridges (not six thin ones) so it survives 29–60 px.
- Logo rework (2026-10-14): the cap is `heat` red (a classic arcade button) instead of volt, which read as neon. The lower ridges resolve into pixels, smooth then half pixels then full pixels, so a real thumb turns into a game. The rings are circles on a 28-unit pixel grid so the pixel rows stay clean. The splash ripple uses `heat` to match the button.
- Logo variants (2026-10-15): `build-brand.ts` takes a variant, and the choice is kept in `brand/variant.txt`. `classic` has five fine ridges on a 28-unit grid. `bold` has three ridges on a 46-unit grid, so the print stays readable at icon and favicon sizes. `bash scripts/brand.sh <variant>` switches the variant and refreshes the mobile, portal and simulator copies.
- Accent is red (2026-10-14): app, portal, simulator and auth emails use `heat` as the accent to match the logo, and volt is gone from the palette. Text on red is ink, at 5.8:1; paper on red would be 2.9:1. Success states (toasts, "live" status, passed review checks, CLI connected) moved to a `success` green (#4CC38A dark, #3F7A00 light), because red now means both "primary" and "error". Where volt and heat used to mean feed and game in the Swipe Contract diagrams, the feed side is now paper. Not changed: the default `games.accent_color` in the init migration, the SDK standalone status dot, the reviewer overlay, `games/_kit` and the avatar palette.

## Integration (lead, Phase 2)
- Challenge share codes only carry a score the caller reached (`share-create` checks `best_scores`, respecting `score.order`) — otherwise anyone could post "beat my 999,999" under their name.
- Events ingest is capped at 600 per user per minute (`events` → 429; the app's bounded queue retries) — trending and ranking signals roll up from client events, so one install must not be able to steer them.
- Session tokens fail verification when `SESSION_SIGNING_SECRET` is under 16 characters, mirroring signing — a missing secret would otherwise accept empty-key HMACs.
- The WebView message origin check is exact (the origin itself, or anything under `origin + "/"`), not a bare prefix — a prefix also matches `https://slug.thumbcade.gg.evil.example`. iOS reports the page URL, Android's WebMessageListener the bare origin; both are unit-tested.
- A card's WebView is keyed by its controller instance as well as its reload counter — a replaced controller (pool reload, Fast Refresh) never saw the old page's hello/ready, so it needs its own page load.
- `create-thumbcade-game --local` writes `link:` dependencies under pnpm and `file:` elsewhere — pnpm copies `file:` directories with only their published files, and the in-repo SDK exports point at `src/`.
- `pnpm dev` stops its children with SIGINT and a 5 s SIGKILL fallback — the Supabase CLI ignores SIGTERM and was left running.
- The seed derives creator-dashboard social numbers from the real seeded rows (60 % of all-time over the last 14 days) and seeds yesterday too — independent synthetic rates showed more likes in 14 days than all time, and an empty yesterday read as a dead game.
- A paused run is dimmed (55 % ink) under the returning chrome — the spec brings the overlay and tab bar back in PAUSED, and without a dim the game's own HUD competes with them.
- The feed caption keeps its natural height (bottom-anchored, tighter rows under Dynamic Type) instead of a max height — at accessibility sizes the cap clipped the meta line; a few points over the preview inset beats losing content.
- Local auth runs with `enable_confirmations = true`, like production — `supabase config push` would otherwise ship the insecure setting, and the guest-upgrade code path gets exercised every day.
- `scripts/shoot.mjs` waits for `load` plus an optional quiet moment, not `networkidle` alone — pages with live game iframes may never go fully idle.
- The Android emulator runs with `-gpu host` (Metal), not SwiftShader — software WebGL kept qemu at ~550 % CPU, and Maestro taps took minutes; with the GPU all eight flows pass in 1–3 min each.
- Maestro's cold-start flow accepts PLAYING, ENDED or PAUSED after the tap — all three are only reachable through PLAYING, and a slow poll can land after a short run ends or after the 20 s idle pause.

## Creator & Games (B)
- SDK types are hand-written mirrors of the protocol (type-level equality tests) — the published package needs no dependency, not even type-only; zod-inferred types would drag zod into the d.ts.
- `@thumbcade/sdk/host` validates with the protocol's zod schemas and is published with zod as an optional peer — hosts need validation; games never load it.
- SDK connects its transport at import (not at `init()`) — an offscreen preload can receive `pause` before the game calls init.
- Start trigger = movement of the active/last pointer sequence (≥ 12 px = swipe), key within 1 s = key, else none — the SDK only sees what happens inside the game document.
- After `input.cancel` the SDK swallows the rest of the gesture at window capture (moves, ups, compat mouse events, click) — "no half-jump" has to hold even for games that ignore pointercancel.
- `tc.loop` passes dt in seconds, 0 on the first frame and after a resume, clamped to 0.1 s — paused time must never become physics time.
- Standalone mock host: storage in localStorage, a local best-score "leaderboard", a shadow-DOM dev HUD whose taps are intercepted at window capture so the game never sees them.
- Reviewer harness serves the game from 127.0.0.1 and the harness from localhost (different origins) with the production CSP, gzip, and the real swipe-contract machine — what it measures is what the app would do.
- Reviewer runs Chromium with site isolation disabled — CPU/network throttling must apply to the game iframe, which otherwise lives in its own renderer process.
- "Fast 4G" = Chrome DevTools preset (9 Mbps down, 1.5 Mbps up, 165 ms adjusted latency) + 4× CPU throttle for the ready() budget.
- Launch games share `games/_kit` (session lifecycle, procedural WebAudio SFX, particles, easing, recognizers, shake/hit-stop, fonts); two OFL fonts are bundled per game: Departure Mono (22 KB) and a printable-ASCII subset of Mona Sans Display Expanded Black (25 KB).
- Kit audio suspends the AudioContext whenever the game is muted or paused — pause always means silence, and a muted preview costs no CPU.
- Game icons are SVG artwork in `games/<slug>/art/icon.svg`, rendered to 1024² PNG by the kit's Vite plugin with sharp at build time.
- `tc.feedback` is delivered only during a run (+1.5 s after `gameplay.end`) and never while paused — attract-mode demos must not buzz someone scrolling past; enforced in the SDK so every game gets it.
- Games create their AudioContext while booting when they launch unmuted — creating it inside the first tap measured 120-160 ms (a long task after ready).
- Reviewer WebGL runs on the real GPU (ANGLE/Metal) on macOS — SwiftShader can't hold 60 fps for the 3D games; Linux reviewers need a GPU host (documented in GAPS).
- Reviewer measures long tasks under the 4× CPU throttle (load + the first 2.5 s of attract mode), then unthrottles for fps (GPU) and the interaction script — fps under CPU throttling measures the reviewer's machine, not the game.
- Reviewer: runtime requests to other origins are reported under `static_scan` — ReviewCheckId has no separate network check.
- Reviewer `gameplay_end`: 25 s without input, then up to 70 s of scripted taps/swipes; "warn" (not "fail") when no game over is observed — a human reviewer checks long-session games.
- Reviewer swipe test mimics the feed: a 220 pt vertical swipe in attract mode with FEED_GESTURE_BEGIN dispatched at the first move step; any gameplay.start during it fails `no_swipe_start`.
- Simulator and game share one origin (`thumbcade dev` serves the prebuilt simulator at `/` and the game at `/__game/` through Vite middleware mode with HMR; the monorepo simulator serves launch games at `/__games/`) — the simulator observes input through the probe, whose listeners register before the SDK's, so it can arbitrate drags the SDK swallows after `input.cancel`. Cross-origin URLs load with Dock/keyboard/wheel navigation only.
- Simulator models the 3-slot pool: the dev game's WebView is recycled two cards away and preloaded OFFSCREEN (pause after ready) when it is a neighbor again.
- Simulator chrome is a visual twin of the app; the controls that matter to a game work (like/save/follow toggles, comments/share sheets that SUSPEND the card, Dock mute, result card, resume pill). Everything else on the chrome is inert, not a fake action.
- creator-publish answers pre-upload failures with HTTP 4xx `{error, message, issues}` (contract request B2); the first publish claims the slug and copies the bundle icon (and poster) into game-assets as the game's profile picture.
- CLI auth: `Authorization: Bearer tc_…` first; if the functions gateway rejects a non-JWT bearer, retry with the anon key + `x-thumbcade-token` (until `verify_jwt=false` for creator-publish is live, contract request B1).
- CLI credentials live in the OS keychain (macOS `security`, Linux libsecret `secret-tool`), else `~/.config/thumbcade/credentials.json` (0600), keyed by backend host; `THUMBCADE_TOKEN` wins for CI.
- `thumbcade dev --device` prints a QR for `thumbcade://dev?url=<encoded http://<lan-ip>:<port>/__game/index.html>` — the app's developer menu opens that URL in a DEV card.
- create-thumbcade-game uses opentype.js 1.3.4 (2.0.0 breaks Mona Sans Display Expanded glyph coordinates, same as the brand build) to turn the bundled OFL fonts into SVG paths, rendered with sharp — real icons and posters with no system fonts or browser.
- Template projects use system font stacks and a `release` npm script (not `publish`, which collides with npm's lifecycle).
- `pnpm games:build` captures posters from attract mode through the reviewer harness (preview insets applied, 405×720 at 8/3 DPR = 1080×1920 JPEG) and ships each poster inside its bundle with `manifest.poster` set.
- Every game in the house style belongs to Thumbcade Studio; the other seed creators each have a look of their own (see "Library expansion: house and creator games (2026-10-17)").
- Pixi games import `pixi.js/unsafe-eval` (it makes Pixi v8 run without eval under the CSP) and stop `Ticker.shared`/`Ticker.system`, driving them from `tc.loop`; Three.js games render inside `tc.loop`, never `setAnimationLoop`.

## Player Platform (A)
- Gesture spike (§5.6) PASSED on iOS 27 (iPhone 18 Pro sim, Expo Go 57) and Android 16 (AVD `thumbcade_pixel`, Expo Go 57.0.9) with the primary approach: RNGH `Gesture.Pan().manualActivation(true)` on the pager (activation decided in `onTouchesMove` from the §5.4 rules held in shared values) composed via `simultaneousWithExternalGesture` with a `Gesture.Native()` wrapping each WebView. Verified by Maestro (`apps/mobile/maestro/spike/`): (a) taps reach the WebView with 0 ms (iOS) / 1 ms (Android) between RNGH `onTouchesDown` and the page's `touchstart` (`Date.now()` on both sides); (b) a vertical swipe in PREVIEW is claimed by the feed and the game is sent `input.cancel`; (c) in PLAYING with `vertical: true` a surface swipe reaches the game (swipe counted, no feed claim) while a pan starting on the Dock moves the feed; plus a `vertical: false` game in PLAYING still yields a deliberate swipe to the feed. The `input.inject` overlay fallback is therefore not needed and not shipped.
- Pan failure rule added on top of the contract's activation rule: the surface pan fails (the game keeps the gesture) once |dx| ≥ 16 pt and |dx| > |dy| — the contract defines when the feed claims, not when it gives up; without this a slow horizontal drag could be claimed late.
- Expo Go on Android shows its developer-menu onboarding once per install; Maestro flows dismiss it conditionally. Android Maestro swipes on the Dock target the element (`swipe from: id`) because a percentage near the bottom lands in the system gesture area.
- Metro runs without `--localhost` (it binds IPv6-only `::1`, which Expo Go on the iOS simulator cannot reach at 127.0.0.1); `REACT_NATIVE_PACKAGER_HOSTNAME=127.0.0.1` keeps the manifest URL local. Android uses `adb reverse tcp:8081 tcp:8081`.
- The Android emulator must not use the default console port 5554: its ADB port 5555 collides with the game-host. Start it with `emulator -avd thumbcade_pixel -port 5562 …` (ADB then uses 5563).
- Edge functions are served by `supabase functions serve --env-file supabase/functions/.env` (the CLI's `supabase start` runtime mounts no functions in this setup and stops serving when the stack restarts). Relative imports of `packages/protocol/src` work inside the edge runtime, so functions validate with the real contract schemas (per-function `deno.json` maps `zod` → `npm:zod@4.6.7`).
- Game host proxies the public `game-bundles` bucket with an in-memory LRU (bundles are immutable), sends the exact §6 CSP plus `frame-ancestors` for the portal and simulator, CORS only for an allowlist (never `*`), ETag/304 and range requests.
- Feed ranking (`rank_feed`) is SQL with weights from `feed_config`; the edge function owns the cursor (`seen` ring, position, last creator/tag) so diversity holds across pages. With a small library the feed recycles least-recently-served games (never the last 6 cards) so it is infinite.
- Exploration slots use Thompson sampling with Beta draws from uniform order statistics in plpgsql; games with < `exploration.maxImpressions` impressions qualify.
- Score integrity: `session-start` issues an HMAC-SHA256 token binding session, user, game and issue time; `session-end` rejects bad tokens, scores over `manifest.score.max`, NaN/negative scores, impossible durations (claimed > server elapsed + 5 s, or elapsed < 400 ms) and double ends. Guests get `accepted:false, reason:"guest"` but still receive their best and today's percentile.
- Push fan-out: pg_cron → pg_net → `notify` every minute; the function base URL and service key live in Vault (`set_runtime_secret`), set by the seed locally and by ops in production.
- Comment filter normalises leetspeak and matches whole words from `public.moderation_words`; 5 comments / 60 s / user; one pinned comment per game.
- Seed deletes seed users one at a time after clearing their social rows in bulk (parallel deletes deadlock on counter triggers). Seed icon/poster URLs carry `?v=<versionId8>` for cache busting.
- Each card is a `CardController` (plain TS) that owns the contract state, executes every `transition()` effect, terminates the bridge (zod + per-type rate limits) and the session lifecycle; React only subscribes (`useSyncExternalStore`). It is unit-tested without React Native.
- The pager keeps a pool of three slots; slot k hosts the card whose index ≡ k (mod 3), so a forward swipe recycles the slot furthest behind. Slot positions are `feedIndex·H − scrollY` on the UI thread; the commit decision runs in the release worklet (`resolveRelease`) and only the activation bookkeeping hops to JS.
- Rules for the surface, two-finger and Dock pans are pushed into one shared value from `gestureConfigFor(phase, controls)` whenever the active card's phase changes; the worklets call the contract's `claims()`/`resolveRelease()` directly (the contract functions are worklet-annotated and transform fine from the workspace package).
- WebView budget: only the focused pager mounts game WebViews; a pushed scoped feed claims the budget and the home feed falls back to posters until it is focused again. The `ready()` timeout pauses while the hosting screen is hidden (hidden WKWebViews stop rAF).
- Shared WebView data store (not incognito) with `sharedCookiesEnabled={false}`/`thirdPartyCookiesEnabled={false}`: keeps the HTTP cache warm between plays; production isolates games by origin (`<slug>.thumbcade.gg`). Navigation is locked to the version's base path, not just the origin.
- Global sound defaults to off; games start muted in previews until the user turns sound on (Dock or Settings); the setting is persisted.
- Idle auto-pause (20 s) means unattended runs never end on their own; the resume pill brings them back.
- Age screen stores only the band, computed from the lower bound of the possible age (birthday may not have passed) so the boundary errs on the protective side. Under-13 players can play age-appropriate games but social features stay locked.
- Comments, likes, saves, follows, reports, blocks go straight to PostgREST under RLS with optimistic cache patches across every query that shows the same game or person; edge functions are only used where a trusted server step is required (ranking, sessions, shares, deletion, push).
- Share codes are members-only (protocol); guests share the plain game URL. The seed's challenges come from named demo members and carry that member's real best.
- `paperMute`/`textMute` (3.4–4.0:1 on ink) is used only for placeholders, disabled states and decorative glyphs; all readable text uses `textDim` or brighter (≥ 7.2:1).
- Dynamic Type: text scales up to ~1.35× (display sizes less); the feed caption is capped at 1.12× because it must fit the fixed `captionHeight` inset that games are told about.
- Cartridge → game page "shared element" is implemented by measuring the cartridge and animating a floating icon into the hero slot (Reanimated 4's shared element transitions need a native feature flag that Expo Go doesn't have).
- Brand marks are rendered from the design-tokens SVG files (embedded verbatim by `scripts/gen-brand.mjs` for `SvgXml`), never redrawn.
- iOS-only WebView props (`dataDetectorTypes`, `textInteractionEnabled`, `keyboardDisplayRequiresUserAction`) are passed only on iOS: on Android/Fabric, `dataDetectorTypes` crashes the RNCWebView props parser.
- `expo-notifications` and `expo-media-library` are loaded lazily: Expo Go for Android logs an error on importing the former and lacks the latter's native module.
- App Store guideline 4.7 (read 2026-10-14 at developer.apple.com/app-store/review/guidelines): HTML5/JS mini games may be offered outside the binary if the app takes responsibility for them and meets 4.7.1–4.7.5. How the player complies: **4.7.1** privacy rules apply to games too (games never see tokens, email, device ids or the real user id; per-game opaque player id), objectionable-content filtering (human review before live, age ratings, comment word filter), report (games, comments, users) and block are in the app, with a moderation queue in the portal; no digital goods in v1 (3.1 untouched). **4.7.2** games get no native APIs: the bridge exposes only lifecycle, score, storage, leaderboards, a share flow and *semantic* feedback that the shell maps to haptics itself. **4.7.3** no data or permission is shared with a game without consent: games get display name/avatar only, no permissions (camera, location, photos) are ever forwarded. **4.7.4** the index of software is the games table/feed with full metadata, and every game has a universal link (`https://thumbcade.com/g/<slug>`, wired as associated domain). **4.7.5** declared-age gate on first launch stores an age band; the feed filters by each game's age rating, and the game page shows the rating.

## Creator analytics and milestones (lead, 2026-10-14)
- A run counts as a play once the game ends it or once it reaches 3 s of active play (`QUALIFIED_PLAY_MS`, mirrored in `feed_config.analytics`; a test keeps them equal) — counting instantly would count a tap followed by a swipe; a long threshold would drop real short runs (a Flapjack death at 2 s). 3 s is twice the 1.5 s fast-skip window. Runs that never qualify show up as bounced starts.
- The public play count moved from session start to qualification, and counts at most 100 plays per person per game per UTC day — the feed's "▶ plays" and the creator's dashboard are now the same number, and one install can't inflate it.
- Playtime is active time in PLAYING while the game runs, measured by the shell (`CardController` run clock) and reported through `session-progress` (once at qualification, then on interruptions, at most every 5 s) and `session-end` — the server clamps it to wall-clock time + 2 s and never lowers it. Wall-clock `durationMs` stays for the impossible-duration check.
- Sessions by the game's creator or by admins are marked `excluded` when they start and never count anywhere — creators testing their own game would otherwise inflate it.
- Per-player aggregates (`game_players`, `game_player_days`) have no client policies; creators see only owner-checked `creator_*` RPC aggregates — the tables hold user ids.
- A player's playtime is recomputed from their sessions in the trigger; only the game's total adds deltas — incremental per-player deltas double-counted when several sessions arrive in one statement (the seed).
- Range player counts are stored windows (`players_7d`, `players_28d`) computed by the rollup, not sums of daily players — summing days counts returning players twice.
- Sources and versions are compared from the daily rollup (`plays_*` by launch reason, the version live when the day was rolled up), not from session scans — cheap at any size and consistent with the headline numbers; release days go to the version that was live at that day's last rollup.
- The funnel is per card view (viewed → started → played → played again); "came back another day" is shown as day-1/day-7 return of new players, not as a fifth funnel step — it counts people, not card views.
- Milestones are awarded right after each rollup (same cron job), once per game, kind and threshold. At most one milestone notification per game per UTC day (the most exciting one wins: taking off, then players, playtime, best day, firsts). Best day and taking off have a 7-day cooldown. The migration awarded existing milestones silently so deploys don't flood inboxes.
- Drops never notify and render in neutral text; only rises use the success color — a creator dashboard informs, it doesn't alarm.
- A milestone is public only after its creator shares it (`share_milestone` → `/m/<code>`); the card links straight into the game, like challenge pages.
- OG cards inline remote images (`imageDataUrl`) — next/og refuses loopback URLs (SSRF protection), so every card with a game icon failed locally; the font path also falls back to the workspace layout because Turbopack dev resolves packages to virtual paths.
- The seed's all-time totals scale the visible 28 days by the game's age (with a launch bump) instead of the old 6–36× multiplier — the dashboard puts all-time and 28-day numbers side by side, so they must agree. Locally the seed dates `playtimeSince` to the first seeded launch.
- The mobile Creator Hub's dashboard links now open `/creator` — `/dashboard` never existed in the portal.

## EU / German compliance (lead, 2026-10-14)
- Legal text lives once, as data, in `packages/legal` (`@thumbcade/legal`): operator details (`OPERATOR`), retention periods (`RETENTION`) and the Imprint, Privacy Policy, Terms and Community guidelines. The app renders it natively (`/settings/legal?doc=…`), the portal at `/legal/<doc>` — the two used to say different things. English only, like the rest of the product.
- The operator's address appears only where the law needs it: the Imprint and the controller block of the Privacy Policy. No "established in" statements elsewhere, no named supervisory authority (Art. 13 only requires stating the right to complain), no consumer-arbitration notice (§ 36 VSBG applies from 11 employees), no ODR link (platform shut down in 2025).
- No cookie banner: the portal sets only the Supabase session cookie and the web player uses local storage for saves the player asked for — both strictly necessary. Adding any analytics or third-party embed changes this.
- Data export is server-side (`account-export`, service role, filtered by the caller) so it includes what RLS hides from players: usage events, hashtag weights, per-player analytics aggregates, sign-in identities. The app shares the JSON; the portal downloads it from `/account/export`. Guests can export and delete too.
- Retention is enforced, not just written down: daily cron `thumbcade-retention` drops `feed_events` partitions older than 90 days (rollups stay) and deletes guest accounts with no sign-in, session refresh or token rotation for 12 months. A test (`scripts/test/privacy.test.ts`) keeps the cron arguments equal to `RETENTION`.
- Web account deletion redirects to `/account/deleted`; a success state inside `/account` can't render because the cleared session cookie re-renders the protected page.
- DSA: the Imprint names one point of contact (Art. 11/12); the Terms describe moderation tools, reporting illegal content without an account, and how to contest a decision (Art. 14/16). As a micro/small enterprise Thumbcade is exempt from the online-platform duties in Art. 19 onwards (complaint system, transparency reports, recommender transparency) — the Privacy Policy still lists the feed's main ranking signals.


## Launch games: licenses and de-cloning (2026-10-16)
- Every game bundle ships its license texts under `licenses/`: `libraries.txt` is Vite's `build.license` report (name, version, license, full text of each bundled npm package) and the kit adds the OFL text of each kit font in the bundle — MIT, ISC, BSD and the OFL all require the notice in every copy, and minified chunks keep none. `.txt`, because the game host, the reviewer and creator-publish already serve it as `text/plain`.
- The game title font is "TC Display Black", a renamed subset of Mona Sans Display Expanded Black — a subset is a Modified Version under the OFL and Mona Sans reserves the name "Mona". `games/_kit/scripts/fonts.ts` rewrites the name table after subsetting (original copyright, vendor and designer kept, license records 13/14 set) and fails if any record but the copyright still says "Mona". Departure Mono has no reserved name and ships unmodified.
- Game mechanics stay free to use, but a launch game must not copy a famous original's look and presentation (German UWG §4 Nr. 3, slavish imitation). Heatfall (then Helix Fall) became a forge: toothed iron grates with cooling slots on hex hubs, coolant vents with a cyan chevron pattern instead of red segments, a faceted ember with a halo instead of a ball, sparks instead of a paint splat on bounce, and its own charge rule (gaps stoke the ember, bounces cool it a notch, five charges melt the next grate and vent the heat front) instead of "three gaps in a row smash". New icon: one gear seen from above with the ember in its gap.
- Neon Chop (then Slice) dropped Fruit Ninja's presentation: no watermelon-coloured produce (hexberry is blue), no blade across a melon in the icon, three market lights under a centred score instead of X strikes top-right with the score top-left, light streaks and sparks instead of juice splats, and the surge cell (arcs into the three nearest produce and cuts them, never static) instead of a freeze item with a frost overlay. Seed comments no longer talk about bombs and fruit.
- Smaller hallmarks went too: Stackd's square ripple outline on a perfect drop is now the new floor's windows blazing, and Voltbrick's (then Breakout Neo's) silver riveted armoured bricks are smoked glass with glare and light cracks.

## Launch game names: trademark clearance (2026-10-16)
- Seven launch games were renamed, display name and slug, after an EU/German trademark check (EUIPO, DPMA and WIPO records via TMview and EUIPO's register, prior use in the German App Store and Google Play, German title protection for games under §5(3)/§15 MarkenG). Slugs are permanent once published, so this had to happen before launch. `THUMBCADE_BUILD_PROMPT.md` keeps the original names as the brief.

## Creator bundle safety (2026-10-17)
- Players are protected by the sandbox, not by reading code: the platform only ever receives a creator's built bundle, and every game runs on its own origin under a CSP with no outside network, with device features switched off and only the fixed bridge to talk through. The checks below close the gaps that sandbox leaves and make the bundle reviewable.
- **File types.** A bundle may only hold web code, data and media (`BUNDLE_FILE_EXTENSIONS` in `packages/protocol/src/publish.ts`), no hidden files, and no native executable under any name (`executableKind`: PE with a real `PE\0\0` header, ELF, Mach-O, universal binaries). `creator-publish` refuses offending uploads before anything is stored; `thumbcade validate` and the reviewer's manifest check report the same; `thumbcade publish` leaves out `.DS_Store`, `Thumbs.db` and `desktop.ini`.
- **Obfuscation fails, minification passes.** `obfuscationSign` in `@thumbcade/cli/checks` looks for obfuscator and packer fingerprints: ten or more `_0x…` identifiers, `eval(function(p,a,c,k,e,…))`, 500+ characters of only `[]()!+`, `eval`/`Function` of `atob`/`unescape`/`decodeURIComponent`, or 500+ `\x` escapes making up 8 % of a file. Calibrated against all 26 game bundles, 235 large library files from `node_modules` (Next.js, Babel, Terser, Vitest, chess.js and more) and the npm builds of Phaser 4.2.1, Pixi 8.22.0 and Three 0.186.1: no hits.
- **WebRTC** isn't covered by any CSP directive, so it could carry data out. The static scan fails on `RTCPeerConnection` and friends (only developer tools such as Babel and Terser mention them; no game library does), and the probe hooks `createOffer`, `createAnswer`, `setLocalDescription` and `createDataChannel` on the prototype, so the reviewer's network check also catches a name built at runtime or a constructor taken from a blank iframe. Clients can't block it: a same-origin `about:blank` iframe hands out a fresh `RTCPeerConnection`, and a host can't inject into a cross-origin frame on the web. What a game could leak is limited to what it has: the anonymous player id, display name and avatar URL, and anything typed into it.
- **Navigation.** The app's WebView already refuses any navigation outside the version folder before a request is made. On the web a game can navigate its own iframe (no sandbox flag prevents it); tested in Chromium, a page with no CSP let a game's redirect reach an outside server with data in the URL. The portal now sends `Content-Security-Policy: frame-src <games origin>` on every page (`apps/portal/src/lib/frame-policy.ts`, wired in `next.config.ts`), and the browser refuses such a redirect before any request leaves. The web player drops a frame that loads within a second of a `frame-src` violation and says the game was stopped. The static scan warns on `location = …`; the reviewer's routing records a frame navigation as an off-origin request.
- **Flashes.** The reviewer captures the page with the CDP screencast at 60 fps (every composited frame) for 3 s of attract mode and up to 30 s of the run, and `services/reviewer/src/flashes.ts` applies WCAG 2.3.1. A general flash is opposing luminance changes of at least 0.1 with the darker side below 0.8; a red flash is opposing changes of at least 20 in (R − G − B) × 320 involving saturated red. Each 10 px cell is tracked as a zig-zag; a 320 px square (10° of view at about 30 cm) makes a transition when a quarter of its cells turn the same way on the same frame (two halves a frame apart count once), so a full-screen flash or a flipping checkerboard counts and moving objects don't: they darken the cells they enter and brighten the ones they leave at once. More than 3 flashes in any second fails. A first version only asked that cells flash in the same second, not at the same moment, and failed Wobble Up for its spring launch (cookies and platforms scrolling fast over a light sky); its recording now measures 0.
- Contract additions, made at the owner's request and additive only: the `flashes` review check id and the bundle file helpers in `packages/protocol/src/publish.ts`.

## Frame rate fixes: riso screens, Lanternline stepping (2026-10-25)
- Longhop and Leapwater ran at 0.8–2.6 fps in iOS WebKit while playing. Cause: every halftone tint was a pattern rotated to its ink's screen angle at fill time, and WebKit (CoreGraphics) fills a rotated or scaled pattern on a very slow path. In the simulator 40 fills drop from 60 to 0.7 fps when the pattern is rotated; the plates, grain and multiply blending were not the problem. `riso.ts` now draws the turned dot grid into the tile itself, and the pattern is only pinned to the paper. A turned grid tiles a square only at angles atan(p/q), so screen angles snap to the nearest one (15° → 14.0°, 75° → 76.0°, 45° stays), within about 1° and with dot spacing under 1 % off. After: 55–60 fps. Leapwater's veil pattern is drawn in device pixels for the same reason. Halftones drawn inside a rotated transform (falling leaves, the kangaroo's death tumble) still take the slow path, but they cover little area.
- Lanternline's sim now advances each frame in equal substeps that add up to the frame's time, instead of fixed 1/120 s steps with a carried remainder. In slow motion and on 120 Hz screens the old stepping alternated frames that moved with frames that didn't. At a steady 60 or 120 Hz the physics is unchanged. Slow-motion entries and the first-run wait ease in over a few frames, and the drawn figure rounds the corner of a catch on a stiff spring (≤ 7 wu, ~0.1 s); collisions still use the body.

That is 181,720 words of 3-16 letters, 468 KB gzipped. The common list (seeding, the pen's demo, "missed") is SCOWL english and american up to size 35: 38,788 words, of which the 10,795 up to size 20 count as everyday words and are revealed first. `scripts/words.ts` builds both from pinned, checksummed downloads; licences ship as `licenses/words.txt`. The common list (104 KB gz) loads before `ready()`; the broad one loads after the first frame and is searched in place by a binary search over the text, so it costs no parsing. Checked on throttled Fast 4G with the list held back 4 s ("stoa" at 2.6 s, accepted on arrival).

Mild hard words made of the commonest letters (ass, arse, rape, damn, crap…) are only kept off straight lines a player could read: checking every bent path for them threw away a third of all boards for words nobody can see. Soft words (an innocent first meaning and an adult second one, or adult topics) are accepted if traced, but never planted, demoed or revealed. The bundle ships hashes of the hard words for the board check, never the words.

The clock is 70 s and a round never runs past 90 s: time back fills the page up to its ninety seconds. A numbered seal every fourth word; using all sixteen letters at least once pays 10 points and 3 s, once.
- Feel: a tile is picked up within 42 % of its width around its centre, so the corners stay dead and a diagonal never snags its neighbours; the finger's path is sampled between pointer events, so a fast stroke can't skip a tile; going back onto the previous tile lifts the stroke off. The traced word shows live above the board with its length and value, and gets a vermilion rule as soon as it is a word we know (an assist, not a spoiler: the board's words aren't listed). Every new letter plucks a marimba note one step higher. A word stamps: the ink soaks back into the tiles, the points fly to the score, long words ring a bell, splash ink and shake the page a little. An unknown word shakes softly and leaves a smudge; a repeat says "already found" and underlines the earlier one; nothing ever costs time or points. ## Curlwall (2026-11-06)
- A house game (Thumbcade Studio, Three.js): free kicks under floodlights. A tap starts the run; an upward flick that starts anywhere in the lower 62 % of the screen kicks. Mild assist: up to 0.9 m outside the post or over the bar is squeezed back just inside, and a flick near a corner ring is drawn toward its centre; anything wilder stays wild. - **The pressure: a rising starter, not a clock.** A sourdough starter at the bottom of the tin rises all the time (0.07 + 0.0085·t units/s), lifting the whole pile toward the rim, and every merge knocks it back, as bakers knock back risen dough: 0.1 units for a gumdrop up to 1.2 for the party cake, 30 % harder per chain link (`src/run.ts`). - **Ladder and jackpot.** Ten tiers were too deep for feed-length runs (nobody baked the top, a quarter of experts reached the second-to-top), so there are nine. - **Physics** (`src/physics.ts`, pure, deterministic, no allocation while stepping): position-based dynamics, 1/120 s steps of four 1/480 s substeps, circles up to 120, O(n²) pairs, mass by area, no restitution (clay doesn't bounce), positional Coulomb friction (μs 0.45, μk 0.3). Three fixes made it stable: overlap that this substep's motion didn't create (a merge swelling into its neighbours, a piece squeezed between two) is eased out without adding speed, and the dough and walls discount those eased pushes too, so a merge lifts the pile a few pixels and never throws it (settled pieces stayed under 6 units/s upward in real runs, against 21 before); hairline leftovers inside a resting stack are resolved in full, or easing them along their slopes made the pile creep; and contacts between pieces still for 0.35 s hold fully, with sideways sleep after 0.5 s, so piles settle to exact stillness instead of drifting. Merges happen on touch (0.03 units of slack), at the contact point, and the new piece swells from its parent's size over 0.14 s; a fresh piece can chain after 70 ms. Drawing interpolates between steps, so motion is even at 60 and 120 Hz.

## Rowlock: speed number grids against one clock (2026-11-06)
- **What.** A Thumbcade Studio game (`rowlock`, Canvas 2D, house fonts and UI, brass accent #C6AA39) from the number-placement family: fill every row, column and box with each digit once. - **Name.** Screened on 2026-11-06 before the folder existed: web search, App Store DE/US/GB through the iTunes search API, Google Play DE, Steam (cc=DE), plus a trademark/brand web search. Rejected: Numberlock ("Number Locks", a number game in the US App Store), Sixfold ("Sixfold: Roll & Match", a dice game in the German and US App Store, and "Sixfold Swarm"), Gridlock (a dozen games: "GRID:LOCK", "Gridlock: Car Jam Puzzle", "Unblock Gridlock" on Steam, Rubik's Gridlock), Once Over (a phrase, no hold), Boxlatch, Tallylock, Chimelock and Rowchime (clean but weak). **Rowlock** (the fork on a boat's gunwale that holds an oar) had no game or app in any store and no Steam title; the only marks found are a dead US filing in class 25 (clothing, 7 Skies Commerce) and the lock brand ROLLOCK (door hardware, "Rollock Mobile Access" in Google Play). TMview refused scripted queries and itch.io's search returned nothing readable, so no register search was done (`docs/GAPS.md`). The name shares no root with the genre's best-known titles.
- **De-cloning.** Nikoli holds SUDOKU in Japan (and has had "Sudoku" apps pulled from the Japanese App Store), so neither "Sudoku" nor "-doku" appears in the title, copy, tags or code, nor "Number Place" (the original magazine name) or "Nanpure"; copy says "number grid", "keys" and "digits", and `test/copy.test.ts` greps the manifest and every source file for them. No newspaper look: no thin black rules on white newsprint, no thick 3 × 3 box borders, no serif digits, no 9 × 9. The board is a brass-and-ink keypad at midnight: every key is a raised cap on a dark plate, one plate per box, with clear space between boxes instead of ruled lines. No "mistakes 0/3" counter and no game over on mistakes, no hearts, no notes toggle, no ad-unlocked hints. Copy names no other game.
- **Why no 9 × 9.** On the 360 px Android viewport a 9 × 9 board with box gaps and the lock-mark margins gives 33-35 px keys (38 px edge to edge), under §12's 44 pt minimum, and a 9 × 9 at speed takes an expert 40+ s, past the run-length bands. The stretch for strong players is harder 6 × 6 grids instead (below).
- **Every grid has one solution and needs logic only.** `src/solver.ts` is a human-technique solver: each round it takes the easiest placement on the board (the last gap in a unit, a digit with one home in a box, then in a line, a key with one digit left), and only when there is none it rules candidates out with a locked digit (pointing/claiming), a naked pair or a hidden pair, then tries again. It never guesses, so a grid it fills completely has exactly one solution. A grid is dug out of a random full solution (`src/gen.ts`): keys are emptied in a shuffled order and stay empty only while the solver still fills the grid. Two numbers grade it: its technique (the hardest one the solve needed; because the solver always takes the easiest move, "one home in a line" means there was a moment with no box single on the board) and its width (how many singles the placed digits show on average along the solve; a narrow grid hides its next move). In 6 × 6 a single in a box is nearly always available, so hard grids are rare among random digs: at 26 empty keys about 20 % need a line single and about 2 % need a key with one digit left or more.
- **The grids of a run.** Grid 1: today's 4 × 4, 9 empty keys, the same for everyone (from `dailySeed`), marked "TODAY'S GRID · NOV 6" with a calendar tab. Grid 2: 6 × 6, 16 empty. Grid 3: 19. Grid 4: 22 (the narrowest of three digs). Grid 5: 24 and must need a line single (up to 40 digs; 94 % meet it). Grid 6 on: 26 and must need a key with one digit left, a locked digit or a pair (up to 160 digs; 91 % meet it, the rest fall back to the hardest dig found). The tag above the board names each one: EASY, STEADY, BRISK, SHARP, TRICKY. Grids after the first come from the run's seed and their index, so the order and timing of the work never change a grid. Daily grid only for the warm-up: learning a 4 × 4 by heart is worth a few seconds at most, and the grids after it are fresh every run (the same fairness reason as Fair Copy). After the bell the keys you didn't reach show their digits in pencil, except on today's grid. `test/gen.test.ts` deals 1,710 grids across the six specs and checks each with an exact solution counter (one solution), the logic solver (fills it, digit for digit the stored solution) and the grade; plus determinism, frame-split dealing and the daily grid.
- **Dealing time.** One dig costs about 0.9 ms in Node (1.7 ms with seven other builders on the machine); grids 1-4 deal in at most 1.9 ms, grid 5 in 5.5 ms median (27 ms worst) and the stretch grids in 35 ms median (134 ms worst) in one go. The game never deals in one go: `Dealer.pump` digs the next grid 3 ms per frame (one dig per frame on a phone taken as 4× slower) while the current grid is played, so a stretch grid is ready in at most ~3 s of play and no frame carries more than one dig. The reviewer measured no task over 50 ms after `ready()`.
- **Input.** A key and a digit make a move, in either order (`src/controls.ts`). Key first: tap an empty key (its row, column and box light up), then a digit on the pad; a wrong digit keeps the key selected, so the next guess is one tap. Digit first: tap a pad digit, or any key that already holds it, and it stays armed (its homes on the board get brass rings); every empty key you tap takes it until all of that digit are in (it then drops itself) or you tap it again. Pad keys show how many of their digit are still to place and lock with a check mark when complete. Everything acts on release (moved more than 18 px is no tap), so a swipe the feed claims never enters a digit. Near misses: a touch in a gap goes to the nearest key (12 px slack); with a digit armed, a touch on the edge of a full key goes to the empty key beside it (14 px); pad keys take touches 4-10 px outside their caps.
- **The run.** 26 s at the first tap, at most 45, burning 1 + 0.08 s per second per 6 × 6 grid after the first. A locked unit gives 0.45 s back, a filled grid 6 s on the warm-up and 6.5 s on the first 6 × 6 (half a second less each grid, at least 3.5). The clock stands still while a grid is dealt (0.8 s) and while a filled grid is celebrated (1.6 s), and says "CLOCK HELD". A wrong digit never sticks: the key shakes, the digit drops off it struck through, any digit it clashes with rings in heat red with a line naming where ("6 IS ALREADY IN THIS COLUMN"), the streak starts over and the clock loses 3 s (2 s on the warm-up, 1 s in the first 10 s of play, so nobody loses in the first ten seconds even tapping a wrong digit every second). The clock is what ends a run; the last 6 s tick and the bar pulses in heat.
- **Rewards.** A right digit pays 10 × the multiplier. Right digits in a row climb tiers with named lines: ×2 IN STEP at 4, ×3 ON A ROLL at 9, ×4 LOCKED IN at 15, ×5 PERFECT SQUARE at 24, each with its own rising arpeggio, sparks and a pop of the meter. Filling the last key of a row, column or box locks it: the unit plays its own digits as a quick tune (every digit has its note on a pentatonic scale), rings a bell, its keys light brass one after another, and a rowlock mark (the oar fork) appears beside a locked row or under a locked column, a locked box gets a brass rim. It pays 25 × multiplier per unit; two units with one digit are a DOUBLE LOCK (+60, two bells a fifth apart, hit-stop, shake), three a TRIPLE LOCK (+180, three bells, and a lamp unless it is the grid's last key). A filled grid is LOCKED: 120 ms hit-stop, a Photosafe tint, shake, confetti, the whole grid lighting in a wave from the last key and playing back as a cascade, a banner ("NOT ONE SLIP · +100" for a clean grid), 150 + 100 × its index points and the time back flying into the score and clock, then the board slides away and the next one deals in key by key. Earned helpers, never sold: each 6 × 6 grid has one spark key (a twinkling star on a key the solve reaches in its second half; filling it pays 50 and a lamp), and a lamp lights the selected key, or the key that is hardest to read right now (the most digits still fit), with its digit, without building or breaking the streak (two held at most). Something lands every few seconds (locks, combos, tier lines, the spark), a filled grid every 10-25 s for good players, and score passing the best gets "PAST YOUR BEST" and a haptic.
- **Feel.** A key or pad key presses down at once and acts on release with a key click; a right digit lands with a thock, its own note, a pop of the key and a few brass squares; points rise off the key and fly into the score, seconds into the clock. Given digits are paper on raised keys, your digits brass on keys that stay pressed down with a brass bar under them, so they read apart by shape as well as colour; finished pad digits show a check, locks show marks, wrong digits a strike, so everything reads muted. Haptics only for tier-ups, triple locks, a filled grid, passing the best and the end. The pool of light under the board warms with the streak.
- **First run, attract, game over.** Until three right digits are in, a ghost fingertip presses the easiest key, then its digit on the pad, with "EVERY ROW, COLUMN AND BOX TAKES 1-4 ONCE" and why that digit goes ("4 IS THE ONE MISSING · TAP 4", "2 HAS ONE HOME HERE"), then never again (`tc.storage` key `taught`). - **Photosensitivity.** The only full-screen light is a filled grid's (and a new best's) tint through Photosafe (brass at 0.2 × 0.85 alpha, at most one every 0.5 s). Lock sweeps light keys one after another (45 ms apart), the filled-grid wave spreads 60 ms a step at 60 % brass, and both are halved under reduced motion; the spark, lamp, nudge and low-clock pulses run at 0.8-1.6 Hz through `light.pulse` and hold still under reduced motion. - **Pilots** (`pnpm --filter @thumbcade-games/rowlock pilot`, 200 runs per skill). - **The wall (`src/board.ts`, `src/geom.ts`).** A 6 × 7 unit wall; dishes are exact shapes with signed distance functions, so "covers" is a geometric fact: a dish on a higher layer covers a peg when its edge comes within the peg's head radius. - **Every wall can be cleared (`src/deal.ts`, `src/solve.ts`).** The jar rules reduce to counts: jars come in a fixed line-up, the first two not yet shipped stand open, a peg goes into the earliest open jar of its colour or onto the shelf, and a colour's pegs fill that colour's jars in order, so where everything is follows from how many pegs of each colour have been pulled, whatever the order. Dealing works in reverse: the dealer pulls the uncoloured wall's pegs in a random order that only ever takes a free one (resting poses, top layers and started dishes first more often), then hands out colours along that order against the jar line-up so that playing it back never holds more than 3-4 pegs on the shelf. Then a share of the colours (10 % on wall 1, up to 50 %) is swapped at random, and the wall is kept only if a depth-first solver with the real jars and the real five-cup shelf (memo on the set of pegs pulled, emptiest shelf first, 1,500 positions) still clears it; otherwise it is scattered again, and after four misses the unscattered deal, which its own order clears, is used. In 270 sampled deals every wall was scattered and solver-verified. `test/deal.test.ts` plays the witness of 480 dealt walls through the count rules, follows the witness of 240 walls through the real run (with real swings), checks the count rules against a peg-by-peg simulation of jars and shelf over 60 random orders, checks the solver against a wall it must refuse, and checks the dealer's shelf cap and determinism.
- **The swing (`src/physics.ts`).** A dish with two or more pegs never moves. Down to one, it is a rigid pendulum about that peg: gravity's torque over the moment of inertia about the pivot (closed forms for plates, platters and boards, a fine grid for the rest), 2.4/s of damping, 1/240 s substeps. Once slower than 0.35 rad/s within 0.05 rad of rest it eases in critically and then sleeps in exactly the pose the dealer used, so a resting dish neither jitters nor creeps (tested to the bit over 5 s for every dish and peg of 12 walls; the longest settle, from upside down, under 6.5 s). With no peg it falls free with the swing's spin and speed plus a little cartoon hop, and lands on the counter the step it reaches it. Falling dishes don't collide. In play, what covers what is the pose on screen this instant, so a dish swinging past a peg blocks it until it has moved on.

Points: 5 a peg, 40 a jar and 30 a dish (150 for the good china, one per wall from wall 2), times the multiplier, and 250 × the wall number plus 10 per second left for a cleared wall. **Danger:** a pulled peg with no open jar and a full shelf. - **Physics** (`src/physics.ts`, `src/aim.ts`). Rotated boxes that rest stably, topple convincingly and never let a fast wad through need warm-started sequential impulses, two-point manifolds, sleeping islands and time-of-impact for bullets: that is Box2D, so planck it is. Fixed 1/120 s steps, 8 velocity and 3 position iterations, shots are bullets with no air drag (so they fly exactly the stepped path the preview, the pilot and the assist use). Wads come back four ways: a **direct hit** (a doodle the wad touches first and knocks out) gives the wad back, once a shot; **every two other knock-outs** draw a new wad (the HUD draws the next wad's outline half-way); a **double knock** and a **landslide** (the second and fourth doodle out with one wad) give one each; a **big topple** (6 pieces knocked off the books by one wad) gives one. - **The table** (`src/table.ts`, pure data, 360 × 640 units; the physics builds its colliders from it and the renderer draws it). It has an arch over the top, and a shooter lane on the right with a slanted one-way gate at its head: a plunged ball passes up, and a ball coming round the arch rolls off the gate into the right orbit lane.

- **Physics** (`src/physics.ts`, pure, deterministic, no allocation while stepping). A fixed 1/480 s substep. Each substep the flippers turn first, then each ball is swept from where it is to where it would be, against everything it could hit:
  - capsule segments (the faces plus round caps), circles, and the inner and outer faces of arcs (a ball that cuts a chord of a curve in one straight step is put back on the circle and turned with it, not stopped);
  - one-way gates;
  - both flippers, as tapered capsules in their own turning frame: the ball's path relative to the rubber, found by conservative advancement on the capsule's distance field.
  - The earliest hit is resolved and the substep continues, up to 8 contacts. Static friction applies only on real impacts, so a ball rolls on a gentle slope instead of sticking.
  - The rubber's surface velocity at the contact point (ω × the lever arm) goes into the impulse, so a ball met near the tip by a full swing leaves fast and one met at the base leaves soft. Restitution is 0.55, with no bounce below 60 units/s so a cradle stays put.
  - Flippers: 58 long, base radius 10.5, tip 6. They rest 29° down and lift to 24° up at 27 rad/s (3,200 rad/s² to get there, about 38 ms for the stroke) and fall back at 17 rad/s. The tips leave 35.6 units (2.2 balls) at rest and 22 when both are level, so no ball is ever pinched between two moving rubbers (the shorter 58 came from exactly that case).
  - Balls meet each other by velocity only (speculative contacts), so one can never shove another through a wall or a rubber.
  - A ball riding a swinging rubber drifts into it by second order (the frame turns under its straight path); `ride` puts it back, and the tests hold that drift under 0.15 units. A safety net that would push a stray ball out counts its corrections, and it is at 0 in every test and every pilot run.
  - Bugs found on the way and fixed:
    - Coulomb friction froze resting balls in the flipper crook.
    - The inlane guide's open end pinched a cradled ball against the rising rubber; the guide now ends above the pivot, so a lowered flipper never holds a ball and a raised one cradles it in a V.
    - Rounding made "touching at t = 0" repeat until the contact budget ran out.
    - Two simultaneous lifeboat saves stacked two balls on the plunger.
- **Flipper feel.** A cradle works on both sides: a ball rolled down an inlane onto a raised flipper is still within about a second and stays put; let go and it rolls down the rubber to be aimed. A tap pass works (from a cradle, let go, wait 0.16-0.20 s and tap 10-20 ms: the ball hops onto the other raised flipper). Late flips are weaker, because the stroke is still accelerating. ## Rattlepile: a bag of marbles against a pile of number blocks (2026-11-14)
- **What.** juicefactory's sixth game (`rattlepile`, Canvas 2D): the volley brick shooter. Numbered toy blocks creep down a play mat one row a volley; a drag aims a wind-up cannon, letting go fires the whole bag of marbles in one stream, and every knock takes one off a block's number. The run ends when a block reaches the floor. `controls.vertical: true` (the aiming drag is mostly vertical), `inputs: ["drag"]`, `session: "medium"`. The other new game from the same shortlist is Scribbledelve. Passed over: a tap-to-jump obstacle runner (too close to Longhop, Flapjack and Duskrail), a gate-and-crowd runner (a third drag-to-dodge runner after Duskrail and Paddlefox), left/right chopping (Six Seven already owns two-sided tapping), a hold-to-stretch bridge (the library has five hold games), a colour-gate hopper (Flapjack's verb again), territory capture (a second 4-way swipe game next to the maze, and the heaviest AI), a peg-drop shooter (the same aim-and-watch beat as this one, weaker), table tennis (Frostwhisk), batting timing, a two-pedal hill climb (needs landscape and two thumbs), city defence, a shooting gallery and a lane defence (none fits a 60-90 s one-thumb session as well).
- **Name.** Screened before the folder was final: the App Store DE/US/GB through the iTunes Search API, Google Play DE (store search), Steam (store suggest, cc=DE) and a web search. No register search (TMview rejects automated requests; see `docs/GAPS.md`).

Nearest hits: "Rattle: Bead Pop Blast" (Google Play), baby-rattle apps and the Rattlesnake board and card games. It shares no root with the genre's best-known titles (no ball, brick, break or -z).
- **De-cloning.** The mechanic is free; the famous originals' presentation is not used. No black field with flat coloured squares and white dots: a cream play mat with a white frame under juicefactory's sunburst, wooden toy blocks with a routed frame whose colour runs lime, banana, orange, tomato, pink, cobalt as the number grows, glass marbles in five colours with a swirl and a shine, and a wind-up toy cannon with eyes instead of a bare launch point. The extra-ball pickup is a +1 ring; the row-and-column item is a zapper star. Copy names no third-party game.
- **The mat and the marbles** (`src/sim.ts`, pure). Seven columns, nine rows of 50 units; the top row is always empty headroom so marbles can get above the pile. Everything runs on fixed ticks, 240 a second, so a volley is a pure function of the pile and the angle and a run plays out the same at 30, 60 and 120 frames a second.
  - A marble is 14 units across and moves 3.25 a tick, so nothing is ever skipped; it is pushed out along the contact normal and reflected, and its speed is renormalised after every bounce.
  - Two blocks side by side are one flat face: a corner that is really a seam belongs to the neighbour, so a marble on the seam bounces straight back instead of glancing off an invisible corner.
  - A marble never settles into a flat left-right rattle: after a bounce it keeps at least a tenth of its speed vertically, in the direction it already had (nudging it downward let it grind along a block's top for a knock a tick).
  - A long volley speeds up twice (×1.6 after 2.5 s of marble time, ×2.4 after 4.5 s) and after 8.5 s the marbles still out are called home, falling straight through everything: about five and a half seconds on the clock at most.
  - The stream leaves in about a second and a half whatever its size (one marble every 1/15 s, down to one every 7 ticks for a big bag).
  - The cannon rolls to where the first marble landed, 24 units clear of the mat's sides.
- **The pile.** A run opens three rows deep with four marbles, so the first volley already has something to rattle between. A row is 2-6 blocks (never full), usually a +1 ring (always until row 8, then 85 %), and now and then a zapper (22 % from row 3). A block's number is `row × (1 + 0.17 × row)` with a spread of 0.6-1.2, doubled for one block in eight after row 3: the bag grows by about a marble a row, the numbers grow faster, and the pile wins somewhere between rows 14 and 20. Gentler curves gave 110-160 s runs.
- **Input** (`src/aim.ts`). Drag anywhere. Dragging down pulls back like a slingshot and the shot goes the other way; dragging up or sideways points and the shot follows the thumb, so both habits work without a setting. The first 16 px decide nothing, the reading can still change until 36 px, and after that it is fixed for the gesture, so the aim never flips. Back to the middle cancels. A dotted guide shows the first marble's path to its second bounce. A drag started while the pile is still stepping down is kept and fired the moment it stops. A tap fires nothing and says how.
- **Economy.** A knock is a point. A smash pays 10 times its place in the volley's chain (capped at 12), 25 more on the last row ("close call"). Volleys in a row that smash something build a streak: ×2 at 3, ×3 at 6, ×4 at 10; a dud volley ends it. A clean sweep pays 100 × (1 + rows/5) and a marble. A thumb that dawdles 7 s makes the pile creep a row by itself, then every 1.9 s until it fires (a fuse along the mat's top edge fills first, and the pile rumbles): that is the idle end, and it costs the streak.
- **Feel.** Every knock wobbles its block and climbs a pentatonic scale through the volley; smashes burst into confetti and chunks with hit-stop and a haptic (rate-limited); chain words at 4, 7 and 10; +1 rings, zaps, streak tiers and sweeps each have their own sticker burst and sound; landed marbles roll along the shelf to the cannon; the last row glows when the pile is close. A new best is cheered mid-run. The game-over card gives rows, smashes, the best chain, the score against the best and one tip drawn from the run. First run: a glove drags back from the cannon and the guide shows where the bag will go. Everything reads muted.

  - A risograph print, not flat pastel blocks on white with drop shadows: four spot inks on warm paper (black key, bright red for the player, blue and sunflower for the rivals), halftone tints with a solid edge, plates a hair off register, a dot-grid sheet.
  - Beetles seen from above, with legs that walk, not sliding squares with player names; no leaderboard of nicknames, no skins.
  - Its own rules: the sheet is finite and finished at a share (15 % on the first, 5 points more each sheet, up to 50 %), then lifted off for a fresh one; the clock is ink that dries and is topped up by printing; loops pay by size; the player's own line is a wall, not a death; a cut costs the line and four seconds, not the run.
  - Copy names no third-party game (tested).
- **The rules** (`src/sim.ts`, fixed ticks, 120 a second, so a run plays out the same at 30, 60 and 120 frames a second).
  - The player walks 7.5 squares a second until the paper ends, where he stops. 8.5 made a turn a 118 ms window; 7.5 is 133 ms and still brisk. A swipe turns him at the next square (kept for half a second), or at once if he is less than a third of a square past one; on his own print he turns round on the spot.
  - A loop is closed by the line alone: the edge of the sheet does not count (the flood that finds the inside starts from every edge square).
  - His own wet line is a wall: he stops at it, and a swipe back along it is refused. If the line shuts him in so that no way home is left, the line is lost ("boxed in"). In the first version crossing his own line smudged it; pilots with a clumsy thumb lost four seconds to themselves in most runs and ended sooner than an idle beetle.
  - Rivals step over each other's lines. When they could smudge one another they did so every few seconds and the sheet emptied itself.
  - A smudged rival comes back after 3.5 s with a fresh 3 × 3 patch at the emptiest of nine places, far from the player.
- **The ink.** 20 s at the start, 26 at most. It dries a second a second on the first sheet and 9 % faster each sheet after. A printed square gives 0.09 s back (5 s a loop at most), smudging a rival 3 s, a finished sheet 10 s on the first and a second less each time (never under 5). Being smudged costs 4 s. An idle beetle's run therefore ends at exactly 20 s on every seed. Under six seconds the bar pulses, the bed doubles its pulse and the last five seconds tick.
- **Scoring.** A square is a point; a loop of 10 squares or more pays double, 25 triple, 50 four times ("good pull", "big pull", "huge pull"). A rival smudged is 100 × the sheet, a finished sheet 150 × the sheet, a loop closed with a rival right on the line 30 ("close shave").
- **Rivals and pilots** (`src/brain.ts`). One brain runs both: rest on the print, pick a way out with room ahead, walk a rectangle, come home; come home early when another beetle is within reach of the line; the bolder ones go for the player's line when it is within 2-4 steps. Five rivals, timid to mean (4.2 to 6.6 squares a second, loops of 2-3 up to 3-6): one on the first sheet, two after. A pilot is the same brain looking one square ahead of the player's beetle and swiping when the plan turns; skill is loop size, rests, how near a rival may come, whether it cuts, whether it sizes loops by where the rivals are, and how often the thumb misses a turn (12 %, 5 %, never).
- **Feel.** A print floods outward from where the loop closed, square by square; its note climbs a pentatonic with its size, with a second voice from ×2 and a roller from ×3; the plates jolt off register on a big pull, a smudge and a finished sheet. A smudged print thins out through the halftone steps and its line breaks into dots. The share and the ink bar swell when they change. A finished sheet is held up for a second and a half (the ink doesn't dry meanwhile) and fades to paper. A new best is cheered mid-run. First run: a dashed loop draws itself out of the print and home again under the word "swipe", until two loops are printed. Everything reads muted.
- **Sound** (`src/cues.ts`, `src/sfx.ts`, `src/sound.ts`). Every event of the run maps to its sounds and haptic in one table, and the game plays only what the table returns, so a test can check that each action and reward has a cue. Under it runs a quiet two-bar bed on the kit's sequencer (104 bpm, a low pulse and a higher answer), which doubles its pulse at 138 bpm when the ink is nearly dry, rests between sheets and rises a tone with each sheet.
- **Copy fit** (`test/copy.test.ts`). Every line is measured with Jost's real advance widths against the plate it is printed on at 360 pt: all ten tips in the strip (and each tip reachable from a run), the stat line and bar label, every banner and its sub-line, both HUD tickets side by side up to 9,999,999 points, the title card beside the action rail, the hint and every popup. The test found two lines that did not fit and they were changed.
- **Run lengths** (headless pilots, 200 seeds each):

    | Skill | p10 | median | p90 | max | median score | median sheet |
    |---|---|---|---|---|---|---|
    | idle | 20 s | 20 s | 20 s | 20 s | 0 | 1 |
    | random swipes | 16 s | 16 s | 32 s | 46 s | 0 | 1 |
    | novice | 34 s | 39 s | 54 s | 69 s | 0.3k | 2 |
    | good | 45 s | 58 s | 79 s | 90 s | 1.4k | 3 |
    | expert | 43 s | 63 s | 85 s | 112 s | 2.4k | 4 |

  The novice pilot reaches the second sheet in 92 % of runs, after 18 s in the median, and nobody who is steering runs dry inside 15 s. Before the sheets were made shorter (20 % and up) and the own-line rule changed, the novice reached sheet 2 in 16 % of runs.
- **QA hooks, build time only.** As Rattlepile: `VITE_AUTOPLAY=novice|good|expert` plays in lockstep without hit-stop, `scripts/shoot-plan.ts` replays the harness seed's run headless and writes `shoot.qa.json` (a long wet line, a big loop being printed, the first sheet finished, the second sheet, a rival smudged, a later sheet, the game-over strip), and `shoot.json` shoots attract, the first-run hint, a real swiped line and an idle game over. QA bundles are built outside the package.

## Long Suit: patience in ink, deal after deal against the clock (2026-11-14)
- **What.** quietmoves' sixth game (`long-suit`, Canvas 2D, Instrument Serif loaded through `kit/font-faces`, the creator's paper, ink and seal; `qm/` helpers and the pen copied from Galley Proof): patience as everyone knows it. Columns of cards, the lower ones face down; a face-up card is laid on a card one higher of the other colour; a run of such cards moves as one; only the pack's top card starts an empty column; each suit goes home in order from the ace; the pack is drawn a card at a time and turned as often as needed. A run is deal after deal against one clock. Tap only, so `controls.vertical` is false. Accent `#5C7F67`, the green of a card table's baize, used for the backs of the cards (CIEDE2000 ΔE 14.2 from every one of the 57 other accents in the tree, Ringblot included, nearest Spotfall `#00873A`; 4.3:1 on ink).
- **Why this archetype.** Asked for the single most popular puzzle archetype still missing, this is it: the most played solitaire there is. It beat group-the-sixteen-words (needs hand-written sets whose quality no test or pilot can vouch for, and English general knowledge) and the marble chain (far less played today, and its aim-shoot-match-three sits beside Spotfall). It had been set aside because a deal takes minutes and Laddersnap already deals cards; the first is answered by short packs (below), and the second by how differently it plays: Laddersnap snaps one card up or down onto a pile, Long Suit builds columns, turns up hidden cards and sorts four suits home, on paper instead of the house's midnight look.
- **Name.** Screened on 2026-11-14 before the folder existed: App Store DE/US/GB through the iTunes search API, Steam (cc=DE), Google Play DE's search page, a web search. Rejected: Deckle ("Deckle: Event games" and "Deckle: Book Companion" in the App Store), Fair Deal (three solitaire apps of that name: "Fair Deal: Solitär Patience", "Fair Deal: Solitaire Classic", "Fair Deal: Word Solitaire"), Red on Black (no app of that name, but it rings of roulette and the stores answer with casino apps), Turnup ("Turn-Up"). **Long Suit** had no game or app anywhere; it is a bridge player's term (the stores answer with bridge trainers), and the suits here do grow long on their way home. No register search was done (`docs/GAPS.md`).
- **De-cloning.** Patience is centuries old and nobody's; what is left out is the look of its best-known computer versions: no green felt, no blue-backed deck, no cards bouncing down the screen at the end, no three-card draw or casino scoring, no bar of undo and hint buttons. The cards are cream paper with a hairline edge, ranks in Instrument Serif, black suits in ink and red ones in the seal's vermilion, a large mark in the middle, court cards without figures (one, two or three ruled rings round the mark), backs cross-hatched in baize green. The pack lies bottom right, under the thumb, with the last three drawn cards fanned to its left; the four homes sit top left over the first four columns. A finished suit gets the qm seal. Copy calls the game patience and names no maker or other game (`test/copy.test.ts`).
- **Short packs, big cards.** A deal of the whole pack takes minutes, a feed session one. So a run starts on a short pack and works up (`SPECS`): ace to five on four columns (10 cards in the pack), ace to seven on five (13), ace to nine on six (15), ace to jack on seven (16), then the whole pack on seven (24), repeated. The highest card of a short pack stands in for the king: an empty column shows its rank in pencil. The cards are sized to the screen for every deal (`src/layout.ts`): four columns get cards 81-99 pt wide, seven get 45-55 pt (45 on the 360 pt phone, the smallest there is), with the homes under the HUD, the pack on the bottom edge and the columns given all the height between. A short run is fanned half a card apart; a long one closes up just enough to stay above the pack, never so far that a covered card's rank is hidden.
- **Every deal can be won by playing what fits.** Being winnable is not enough for a clock game: a first version dealt any layout the solver could win, and the good and expert pilots still played themselves into a dead end 0.5-1.4 times a run. So the dealer (`src/deal.ts`) lays a shuffled pack out and plays it to the end by natural play (`src/natural.ts`: a card home, a run moved to turn up the card under it, the drawn card laid on a column, a column cleared for the pack's top card, otherwise the pack), once taking the first such play every time and 24 more times taking any of them at random; only a layout that all 25 win is dealt, and the first playout's taps are kept as the witness. It takes 1.6, 2.3, 5.0, 17.5 and 11.0 shuffles on average for the five packs, 0.3-1.7 ms a deal (5.4 ms at worst, Node), and the next deal is prepared 2 ms a frame while the current one is played. `test/deal.test.ts` plays the witness of 600 dealt deals tap for tap through the game's own tap function, plays 3,000 further random-order playouts (under 1.5 % may lose; measured 0.0-0.5 % by pack), checks the pack and layout of every deal, that an unfiltered shuffle is turned down more often than not, and that a deal depends only on the seed, the level and the redeal however the work is split.
- **One tap.** A tap on a card sends it where it fits: a column's top card home, else the run from the tapped card onto another column (one with cards before an empty one). The whole column is the target, and the game is generous with it: a tap on a top card that cannot go home moves the whole run; a tap above the face-up cards counts as the top card; failing that it tries the top card home, then shorter runs. A tap on the drawn cards plays the top one; a tap on the pack draws, or turns the drawn cards over when the pack is out (an arrow in the empty place says so). A card acts on release within 22 px, so a swipe the feed claims never plays one. After every tap, cards that can go home without a second thought go by themselves (an ace, a two, or a card both of whose lower opposite-colour cards are home), and once nothing lies face down the rest of the deal sweeps itself home, lowest card first, wherever it lies. There is no drag, no undo and no taking a card back from home.
- **Dead ends and the pen.** A solver that sees every card (`src/solver.ts`: depth first, a memory of every table seen with the columns in sorted order, the pack and drawn cards treated as one hand since any of them can be reached) is asked two things. After a whole pass through the pack with nothing played, or a tap that fits nowhere with the pack gone, it tries every legal move (up to 20,000 tables, 2 ms a frame): if nothing wins, or it cannot tell and nothing at all can be played, the lane says "no way home from here. dealt afresh." and a new deal of the same size is laid 1.1 s later with the clock held; cards already home keep their points. For a first run, and after four idle seconds, a quicker search (2,500 tables) finds a tap on a winning line and the pen points at it; when it finds none in time the pen points at the first natural play. Pilots are dealt afresh 0.01-0.07 times a run.
- **The run.** 25 s on the clock when the first deal is laid, 40 at most, burning 1 + (t/75)^1.7 seconds a second. A card sent home by hand gives 0.28 s back, a card turned up 0.25 s, a cleared deal 5.5 s (0.6 s less each deal, at least 3). The clock stands still while a deal is laid (0.7 s), while the last cards sweep home, while a cleared deal is cheered (1.3 s) and while a dead one is replaced. A tap that fits nowhere costs nothing but the time it took. The clock is what ends a run; an untouched one ends after 24.4 s on every seed.
- **Rewards.** A card home pays 10 times the multiplier and a card turned up 5. Cards sent home within 3 s of each other are a chain: ×2 at four, ×3 at nine, ×4 at fifteen, ×5 at twenty-four, each with its line ("nine home in a row · ×3") and a chord; the sweep at the end of a deal runs the chain up at thirteen cards a second, so finishing a deal is the richest moment in it. A cleared deal pays 100 times its number plus 5 a second left. A finished suit is sealed. Passing the best gets its line and a haptic.
- **Feel.** A pressed card (and the run on it) lifts on its shadow; cards fly to their place in 0.17 s (0.26 s home), a run a card at a time; a card turned up flips on its way; each card home plucks the next note up a pentatonic, so a chain and above all the sweep climb; a card laid is a soft knock, the pack a flick of paper, the turned pack a rustle; a tap that fits nowhere shakes the card and nothing else. A new deal is dealt out from the pack a card at a time. The clock is an ink rule across the page that shortens, seal red and pulsing (2 Hz at most) with a tick each second in its last five; the multiplier sits top right over a rule that runs out with the chain. News (the deal, a multiplier, a cleared deal, a dead end) shares one lane under the clock. Haptics only for a new multiplier, a cleared deal, a dead end, passing the best and the end. Everything reads muted.
- **First run, attract, game over.** Until a card has moved, then until one is home, then until a deal is cleared, the lane reads "tap a card: it goes where it fits", "red on black, one lower", "aces go home, then up in suit", and the pen points at a tap that leads home (`tc.storage` key `taught`). Attract mode is the real game played by a pilot who misses nothing on the first two deals with the clock held, under quietmoves' title block ("no. 318 · patience", "Long Suit", "red on black, one lower. send every suit home.") with "tap to begin" and the best above the caption, all inside the preview insets. Game over: the lane says "time", the table pales under a wash of paper, `gameplay.end` follows 0.6 s later, and a slip above the caption and left of the rail gives the score against the best, deals, cards home and the longest chain, a rule of this run against the best, and one tip picked from the run (never tapped, no card home, taps that fit nowhere, never drew, few cards turned up, no deal cleared, short chains, the long columns); `test/copy.test.ts` reaches every one of the eight.
- **Copy fit.** Every line of news, every tip and the game-over lines are measured in the test with Instrument Serif's own advance widths and kerning (the shipped woff2 through opentype.js) against the lane and the slip on the 360 pt phone, at full size; the title and its dek may close up, to 32 and 13 px at least.
- **Photosensitivity.** The only full-screen light is a cleared deal's and a new best's tint through Photosafe (baize green, 0.12 alpha at most, at least 0.5 s apart); the low clock's rule pulses at 2 Hz at most and holds still under reduced motion, which also sets cards down without flight, flips or shakes. Reviewer flash meter: 0 flashes in any second in the review run (26 s); at most 1 flash and 0 red flashes in any second across 33 s of an autoplayed expert run (the cleared deal's tint; the limit is 3).
- **Pilots** (`pnpm --filter @thumbcade-games/long-suit pilot`, 200 runs per skill; the pilot sees the face-up cards and the top drawn card, looks 0.28-1.8 s before a tap (36-60 % of that for the pack), notices each natural play that is there 50-96 % of the time, taps some other card 1-14 % of the time, and follows the pen 70-100 % of the time): run length p10/median/p90 novice 27/37/38 s (longest 47), casual 37/41/49 s (56), good 51/60/63 s (73), expert 72/81/86 s (88); deals cleared (median) 1, 1, 3, 5; cards home 23, 37, 88, 181; top multiplier ×3, ×4, ×5, ×5; median score 0.6k, 1.1k, 3.7k, 8.9k; at least 15.6 s on the clock at 10 s. Random tapping ends after 28/39/50 s, 60.4 s at most.
- **QA hook, build time only.** `VITE_AUTOPLAY=novice|casual|good|expert` lets that pilot play the run through the same taps as a finger; a normal build has none. `shoot.json` (normal build) shoots attract, the first-run line and an idle game over; `shoot.qa.json` (a `good` autoplay build, built outside the package) the mid-run shots. `pnpm --filter @thumbcade-games/long-suit icon` redraws the icon with the ranks as glyph paths.
